OneDriveの同期で困らないファイル名とフォルダ階層の決め方

要点

同期で困りにくい名前と階層は、使用できない文字や名前を避け、保存場所全体を短くする方針で決めます。書類を見分けるための情報を残しながら、フォルダとファイル名の重複を減らすのが出発点です。社内の命名案を作ったら、普段の保存先とアプリで開くところまで確認し、引き継ぎ用の手順に残します。

公開：2026年11月4日／情報の確認日：2026年11月4日（出典はこの記事の最後）

この記事は、OneDriveの同期で困らないファイル名とフォルダ階層の決まりを作りたい小さな会社の事務担当者が、使えない文字と保存場所全体の長さの確かめ方を整理するためのものです。

公式ページ・公式ヘルプなどの一次資料を2026年11月4日に確かめました。機能や制度は変わることがあるので、使う前に各ページで最新の状態を確認してください。法律・税務・労務の判断や、効果を約束するものではありません。

例は説明のための架空の例です。確認表や作例は、当社の考えをまとめたもので、公式の機関が示しているものではありません。

  1. 使えない文字と名前を先に除く
  2. 長さはファイル名だけで数えない
  3. 名前を直す操作と社内の確認順を分ける
  4. 社内の命名案は浅い階層と組み合わせる
  5. 変更後は同期状態と開けることを確認する
  6. 確認表
  7. 自社の事務の手順まで形にしたいとき

1．使えない文字と名前を先に除く

確認日：2026年11月4日。

OneDriveでは、ファイル名とフォルダ名に半角の `"` `*` `:` `<` `>` `?` `/` `\` `|` を使用できません。 名前の先頭と末尾のスペースも使えません。 また、ファイル名のどの位置にも `_vti_` を含められません。

見た目の整え方を考える前に、名前として使えるかを確認します。ファイルの名前だけを調べて終わらず、保存先に並ぶフォルダ名も確認の対象に含めるとよいです。

社内の運用では、書類を区切る記号をあらかじめそろえると、担当者ごとの判断を減らせます。長い文章を名前に貼り付けるより、書類の種類や対象を短く表す方針にすると、後から名前を直すときにも迷いにくくなります。

2．長さはファイル名だけで数えない

OneDriveとSharePointのクラウド側では、ファイル名を含むデコード後のパス全体が400文字を超えることはできません。 一方、Excelの公式仕様表では、ファイル名の長さはパスを含めて218文字とされています。

このため、社内の基準を作るときは、クラウド側の上限だけを採用せず、実際に使うアプリ側の制限も照合する進め方にします。パスはファイルの保存場所を表す文字列です。名前を短くする検討には、途中に並ぶフォルダ名も含めます。

まず、普段の保存先と、そこから開くアプリを担当者に確かめます。次に、名前が長い書類や深い場所にある書類を選び、保存先の階層を書き出します。末端の名前だけを削るのではなく、上位のフォルダ名を短くできるか、同じ説明を繰り返していないかを見る順番です。

保存先の基準を決めた後も、余白を残す考え方が必要です。書類の種類や版の表示を後から足すことを見込み、上限いっぱいを社内の目標にしない運用にします。

3．名前を直す操作と社内の確認順を分ける

Windowsで名前を変更する操作は、エクスプローラーを開き、対象のファイルやフォルダを選択してF2キーを押す手順です。 Excelの特殊文字に関する対処法でも、エクスプローラーで名前を変更し、問題の文字を取り除く方法が示されています。

社内で変更作業を進める際は、先に元の保存場所と変更案を控えます。その後、確認用のコピーを使って、新しい名前で保存し直すところから確かめるとよいです。元の書類をまとめて変更する前に、利用者が必要な書類を見分けられるかも確認します。

確認する順番は、書類の識別、名前の制限、保存先の長さ、変更後の利用です。機械的に短くする作業を先に進めると、見分けるための情報まで削ってしまうため、残す情報を決めてから変更案を作ります。

フォルダを浅くする案では、どの範囲の書類を動かすかも書き添えます。名称だけの変更と保存場所の変更を分けて記録すると、確認する側が変更前後を追いやすくなります。

4．社内の命名案は浅い階層と組み合わせる

以下は、公式の制限とは別に考える社内運用の案です。フォルダには業務や状態、ファイル名には書類の種類と対象を持たせ、同じ説明を重ねない形にします。短くするだけで意味が分からなくなる略語は避け、後任者が見て判断できる言葉を残します。

見直す対象変更前の考え方社内ルールの案
階層担当部署、担当者、対象、書類の説明を順に重ねる`案内\提出用`のように業務と状態を軸にする
フォルダ名長い説明文をそのまま名前にする「提出用」「確認中」のように役割を短く示す
ファイル名上位フォルダと同じ説明を重ねる`案内文_会場変更.docx`のように種類と対象を示す
変更の記録新しい保存場所だけを伝える元の保存場所、新しい保存場所、確認する人を控える

表の文字列は命名の案であり、そのまま全社へ適用する規則ではありません。別の場所へ取り出して使う書類は、ファイル名だけでも内容が分かる情報を残すとよいです。短縮後の名前を見て用途が判断できない場合は、略し方を戻して、階層の重複を減らす方向で検討します。

階層の深さは、社内で扱う書類を見ながら決めます。フォルダを開くたびに同じ名称が現れるなら、重複する説明をまとめる候補です。逆に、同じ場所へ集めた結果、利用者が別の書類と取り違えるなら、分類を残すか、ファイル名に見分ける言葉を足す方向で調整します。

引き継ぎ用には、保存先の決め方、残す情報、変更時の確認先をまとめます。例外が出たときの相談先も添えると、後任者が独自の略語や階層を増やす前に判断を合わせられます。

5．変更後は同期状態と開けることを確認する

OneDriveの赤い円に白い十字の印は、ファイルやフォルダを同期できない状態を示します。

変更後の確認では、エラー表示の有無と、目的の書類を普段のアプリで利用できるかを分けて見ます。保存した名前と場所を確かめたうえで、利用者の通常の手順から開き、内容を確認して保存できるかを見ます。名前が変わったことだけをもって、確認済みにしない運用です。

問題が残る書類は、さらに短くする変更を重ねる前に、対象の保存場所と画面に出たメッセージを控えます。どの操作で止まったかも記録すると、名前の修正で進めるか、別の設定や利用環境を確認するかを相談しやすくなります。

共有相手がいる書類では、作業者の画面だけで確認を終えず、相手が普段使う入口から対象を見つけられるかも確認の項目に入れます。手順書や管理表に保存先を書いている場合は、その記載も変更の対象として扱い、確認する人を決めておきます。

確認が済んだ範囲を関係者へ伝え、保留中の書類と分けておきます。変更前後の対応が追える状態で引き継ぐことまでを、命名ルールの運用に含めるとよいです。
