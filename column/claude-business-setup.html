Claudeを会社で使い始める前に確認すること。TeamとEnterpriseの違い、データの扱い、管理者の決め方

要点

Claudeを会社で使うときは、個人のアカウントではなく、法人向けのプラン（Team または Enterprise）で契約するかを先に決めます。Anthropic の公式ページでは、Team は2〜150席の席単位、Enterprise は最低20席とされ、どちらも、入力した内容は既定ではモデルの学習に使わないと書かれています。ロールの設定・監査ログ・データ保持の設定などは、Enterprise にあって Team にない機能として載っています。使い始める前に、使う業務・入力してよい情報・管理者・退職時の手順を社内で決めておきます。

公開：2026年11月1日／情報の確認日：2026年11月1日（出典はこの記事の最後）

この記事は、会社や事務所で Claude（Anthropic）を仕事に使い始めるときの、最初の確認をまとめたものです。

料金・プラン・設定の内容は、2026年11月1日に Anthropic の公式ページで確かめました。プランや料金は変わることがあります（料金ページにも変更があると書かれています）。契約する前に、公式ページでお確かめください。

「社内で決めること5つ」と確認表は、当社の考えをまとめた作例です。Anthropic が示しているものではありません。

  1. 法人向けのプランは、Team と Enterprise
  2. 入力した内容は、モデルの学習に使われるか
  3. 管理者を決め、メンバーの招待と削除のしかたを知っておく
  4. 使い始める前に社内で決める5つ
  5. 契約の前の確認表
  6. 当社に相談するとき

1．法人向けのプランは、Team と Enterprise

Anthropic の料金ページには、個人向けのプランとは別に、組織向けとして Team と Enterprise が載っています（2026年11月1日確認）。会社の仕事に使うときは、まずどちらで契約するかを決めます。違いのうち、ページに書かれている主なものは次のとおりです。

項目TeamEnterprise
対象と契約の単位2〜150席のチーム向け。席（ユーザー）の数で契約する最低20席。席の料金に加えて、利用量に応じた料金がかかると書かれている
料金の表示ドル建て・税別。席の種類（Standard・Premium）と、年額か月額かの請求で金額が違うドル建て・税別。年額請求・最低20席として表示されている
シングルサインオン（SSO）・請求と管理の一元化ありあり
ロールベースのアクセス・SCIM・監査ログ・Compliance API・データ保持の設定「なし」と表示されている「あり」と表示されている
入力した内容のモデルの学習への利用既定では使わないと書かれている既定では使わないと書かれている

この記事では、料金の金額は載せません。席の種類や為替で変わるため、契約の前に公式の料金ページで確かめてください。ページには、価格とプランは変更されることがあるとも書かれています。

2．入力した内容は、モデルの学習に使われるか

Anthropic のプライバシーセンターの記事（最終更新 2026年3月16日）は、Claude for Work（Team・Enterprise）や API などの商用の製品について、チャットやコーディングのセッションを、参加を選ばない限りモデルの学習に使わないと書いています。個人向けの Free・Pro・Max の扱いは、同じページではなく別の記事で説明されています。会社の仕事の入力を、個人のアカウントでするかどうかは、この違いを踏まえて決めます。

例外として、フィードバックの機能（評価ボタン）などで、利用者が明示的に Anthropic へ送った内容は、学習に使われることがあります。社外秘の内容を扱う画面では、この機能を使わない、というルールも決められます。

同じ記事は、商用のお客様の場合、お客様が個人データの管理者（コントローラー）にあたると書いています。入力する情報の範囲は、会社として決める必要があります（個人情報や、取引先と秘密を守る約束をした情報を入れてよいか）。

3．管理者を決め、メンバーの招待と削除のしかたを知っておく

Team と Enterprise の組織には、管理者の役割として Owner と Primary Owner があります。Primary Owner は組織に1人だけで、Owner・Primary Owner は自分自身を組織から削除できません（別の Owner か Primary Owner に削除してもらう）。請求の設定を開けるのも、Owner と Primary Owner だけです（Anthropic の「メンバーの管理」の記事・2026年11月1日確認）。

場面公式の記事に書かれていること
メンバーを招待する管理者以上が、組織の設定の「Members」から追加する。メールアドレスは組織で許可したドメインのものにする。まとめて追加する方法もある。招待メールは発行から21日で期限が切れるので、期限が過ぎたら招待し直す
招待した人が承諾する前承諾前の保留中の人も、席を使う
メンバーを外す（退職など）メンバーの行のメニューから外す。外された人は、すぐに組織へアクセスできなくなる。席は空くが、契約している席の総数は自動では減らない
SSO を使う組織ユーザーの自動追加（JIT。Enterprise は SCIM も）を使える。使う前に、席の空きを Owner か Primary Owner が確保する必要がある

外すときの席の扱い（総数は自動で減らない）は、費用に関わります。誰が席の数を見直すかも、あらかじめ決めておきます。

4．使い始める前に社内で決める5つ

  • 使う業務を1つ：たとえば「毎月の請求書の下書き」「会議メモからの議事録」。最初から全員に全部の業務を任せない
  • 入力してよい情報：個人情報・取引先と秘密を守る約束をした情報・未公開の数字を、入れてよいか。入れない場合の言い換え（架空の名前に置き換えるなど）
  • アカウントの種類：仕事の入力は会社のプランのアカウントだけで行い、個人のアカウントには入れない、というルール
  • 管理者と連絡先：Primary Owner と、もう1人の Owner。担当が替わったときの引き継ぎ先
  • 見直しの日：プランや設定は変わるので、月に1回は公式ページと自社のルールを見比べる日を決める

社内ルールの作り方は、生成AIの社内ルールの作り方にまとめています。AIの出力を人が確かめる手順は、業務ごとに決めます。

5．契約の前の確認表

確認確かめること
□個人のアカウントではなく、法人向けのプラン（Team か Enterprise）で契約するかを決めた
□必要な機能（ロールの設定・監査ログ・データ保持の設定など）が、選ぶプランにあるかを料金ページで確かめた
□料金（席の種類・年額か月額か・税別）を公式の料金ページで確かめ、契約の日付を記録した
□入力した内容が既定ではモデルの学習に使われないことを、プライバシーセンターの記事で確かめた
□入力してよい情報と、入れてはいけない情報を、文章にした
□Primary Owner と、もう1人の Owner を決めた
□退職・異動のときに、メンバーを外す担当と、席の数を見直す担当を決めた
□プランや設定を、月に1回見直す日を決めた
