OneDriveの社外共有で相手に確認コードが届いたらどうする

要点

OneDrive の外部共有のヘルプでは、Microsoft アカウントを持っていない社外の相手には身元を確かめるためのワンタイム パスコードがメールで送られ、相手はコードを受け取ったら確認画面に入力してファイルを開くと案内されています。送信側はコードの値を聞き取らず、招待した宛先と対象資料を照合し、相手に資料が開けたかを確認する運用にするとよいです。引き継ぎには、止まった画面と対応の状態を残します。

公開：2026年11月5日／情報の確認日：2026年11月5日（出典はこの記事の最後）

この記事は、OneDriveで社外の相手に共有した資料について、相手から確認コードが届いたと連絡を受けた小さな会社の事務担当者が、受信者本人の入力の流れとコードの有効期間、古いリンクのアクセス拒否、受付と引き継ぎの記録を確かめる流れをまとめたものです。

公式ページ・公式ヘルプなどの一次資料を2026年11月5日に確かめました。機能や制度は変わることがあるので、使う前に各ページで最新の状態を確認してください。法律・税務・労務の判断や、効果を約束するものではありません。

例は説明のための架空の例です。確認表や作例は、当社の考えをまとめたもので、公式の機関が示しているものではありません。

  1. 招待した宛先と共有の対象をそろえる
  2. 受信者がメールを見て入力を進める
  3. 期限切れと古いリンクのアクセス拒否を分ける
  4. 問い合わせの記録には値より状態を残す
  5. 後任には対象資料と次の確認先を渡す
  6. 確認表
  7. 自社の事務の手順まで形にしたいとき

1．招待した宛先と共有の対象をそろえる

製品の手順・機能の確認日：2026年11月5日。

対象は、職場または学校アカウントで社外の特定の相手にリンクを送る共有です。外部共有のヘルプの適用先は、Microsoft ListsとOneDrive for Businessです。Microsoft 個人用アカウントでサインインした場合は、Microsoft 個人用アカウントを持つユーザーのみを選択でき、同じヘルプの手順は［職場または学校アカウント］と［個人用アカウント］のタブに分かれています。この記事は、職場または学校アカウントのタブの内容を扱います。社内の引き継ぎにも対象の利用環境を添えるとよいです。

招待した相手に限定したリンクを作るときは、リンク設定で［特定のユーザー］を選びます。OneDrive の Web サイトからメール招待を送る手順では、［名前、グループ、またはメール］欄に相手のメールアドレスか連絡先の名前を入力します。相手から問い合わせが来たら、送信した宛先と、相手が確認している受信先を照合するところから始めます。

連絡を受けた担当者は、どの資料についての問い合わせかを特定します。似た名前の資料がある場合も、開こうとしている対象をそろえてから案内すると、別の資料について確認を続ける行き違いを避けやすくなります。

2．受信者がメールを見て入力を進める

公式FAQでは、SharePoint Online のワンタイム パスコード認証は2026年10月中に商用テナントで廃止され、商用テナントでの新しい外部共有には Microsoft Entra B2B との統合がすでに有効になっていると案内されています。Microsoft Entra の電子メール ワンタイム パスコードは、Microsoft Entra ID や Microsoft アカウントなどの他の方法でゲストを認証できない場合に、そのゲストを認証する方法です。この認証では、受信者が共有先への直接リンクまたは招待メールから進み、ブラウザーにコードの送信案内が出たら［コードの送信］を選びます。パスコードは受信者のメールアドレスに送られ、受信者はメールからパスコードを取得してブラウザーのウィンドウに入力します。メールがすでに届いている相手には、送信の操作を繰り返す説明から始めず、入力画面が手元にあるかを尋ねるとよいです。

送信側の案内は、コードをこちらに読み上げてもらう形にせず、相手の画面での操作につなげます。問い合わせの記録にも、届いた値を転記しない運用にします。

認証後は、共有された内容の表示、またはサインインの続きへ進めます。入力できたという返事だけで連絡を終えず、依頼した資料の内容まで表示できたかを確認するとよいです。途中で別の画面が出た場合は、その表示内容をもとに次の対応を決めます。

3．期限切れと古いリンクのアクセス拒否を分ける

入力までに時間が空いたとき

この認証方式のコードは30分で無効になり、経過後は受信者が新しいコードを要求する必要があります。この期限は、ここで扱う認証方式のコードについてのものです。入力までに時間が空いてコードが無効になった場合は、共有先の設定変更を始める前に、受信者側で新しいコードを要求してもらう流れになります。

以前は開けたリンクが使えないとき

同じFAQでは、Microsoft Entra B2Bのメールによるワンタイム パスコード認証は廃止されないと案内されています。商用テナントで2026年10月中の従来のSharePoint OTPの廃止が適用され、一致するゲストアカウントがない場合、外部ユーザーは以前の［特定のユーザー］リンクでアクセス拒否を受けます。古いリンクでのアクセス拒否は、共有元の管理者へつなぐとよいです。連絡には対象資料と招待した宛先、表示された内容を添え、担当者の判断で共有範囲を広げる変更を進めない運用にします。

4．問い合わせの記録には値より状態を残す

ここからは当社の整理です。

社外に送った確認用の資料について問い合わせを受けた場面を考えます。受付の記録は、受信者がどこまで進んだかと、誰が次に対応するかを読み取れる形にまとめます。

相手からの連絡受付記録に残す状態担当者の対応
メールは届いたが入力していない本人の入力待ち手元の入力画面から進める案内
入力後に資料が表示された表示できたことを確認済み問い合わせの対応を終了
入力後も資料が開かない表示内容を確認中対象と宛先を照合して確認先へ連絡

表に残すのは作業の状態です。メール本文の丸写しや画面全体の添付を通常の受付方法にせず、対応に必要な表示だけを書き留める形が考えられます。

メールが届いた段階、入力した段階、資料が開いた段階は、別の状態として扱います。返事が止まった段階も残しておくと、後任が同じ質問を最初から繰り返さずに対応を引き継げます。

5．後任には対象資料と次の確認先を渡す

担当を交代するときは、対象資料、招待先、直前の表示、相手への案内、次の連絡先をまとめます。秘密の値を記録に加えるより、何を確認し終え、どこが未解決かを明らかにすることが大切です。

相手に操作の続きを案内済みなら、返事を待っている状態まで記します。社内の確認担当に引き継いだなら、誰が返答するかも添えるとよいです。対応中とだけ記したままにせず、次の担当者が動ける情報を残します。

対応の終了は、目的の資料を開けたことについて相手から返事があった段階で記録する運用が考えられます。開けない状態が続く場合は、未解決のまま確認先と次の対応を引き継ぎます。

6．確認表

公開・共有の前に、この表で確かめます。

確認確かめること
□招待した相手と、連絡してきた相手の受信先を照合したか
□問い合わせの対象資料を特定したか
□届いた値を担当者へ送ってもらう案内になっていないかを確認したか
□相手がどの画面まで進んだかを確認したか
□入力の完了と、目的の資料が表示できたことを分けて確認したか
□未解決の場合の確認先と、次に対応する担当者を記録したか
