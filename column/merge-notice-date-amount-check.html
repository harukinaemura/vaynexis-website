差し込み通知書の日付や金額が元データの表示と違うのはなぜか

要点

差し込み通知書の日付や金額が元表と違って見える原因の一つとして、Microsoft の資料は、データソースで書式を設定しても、データをメイン文書に差し込むときにその書式が保持されないと説明しています。ただし、この資料は適用先に Microsoft Word 2010 とだけ記載されており、OLEDB で Access または Excel のデータソースに接続した差し込み印刷を扱っています。お使いの環境に当てはまるかは、この記事では確かめていません。当社の整理では、元の値、表の表示形式、出力文面を分けて照合し、値の誤りか見せ方の差かを確かめます。修正箇所と確認した出力を残してから、送付の判断へ進むとよいです。

公開：2026年11月3日／情報の確認日：2026年11月3日（出典はこの記事の最後）

この記事は、差し込み印刷で作る通知書の日付や金額が元の表と違って見える場面に困っている小さな会社の事務担当者が、元の値・表の表示形式・出力文面を分けて確かめる流れをまとめたものです。

公式ページ・公式ヘルプなどの一次資料を2026年11月3日に確かめました。機能や制度は変わることがあるので、使う前に各ページで最新の状態を確認してください。法律・税務・労務の判断や、効果を約束するものではありません。

例は説明のための架空の例です。確認表や作例は、当社の考えをまとめたもので、公式の機関が示しているものではありません。

  1. 元の値と、表で見える形を分ける
  2. 通知日が読みにくい場面で、照合の軸を決める
  3. 見た目の差と、内容の差で確認先を分ける
  4. 差し込み結果は、記号と前後の文章まで読む
  5. AIには差の説明案を頼み、確定は人が担う
  6. 確認表
  7. 自社の事務の手順まで形にしたいとき

1．元の値と、表で見える形を分ける

公式資料の確認日：2026-11-03（以下の製品説明に共通）。各ページの最終更新日は確認できていません。

Microsoft の Excel for Mac 向けの案内では、数値の表示形式は、実際の数値を変えずに日付や時刻などの見た目を変えるものとされています。Excelの通貨形式では、通貨記号を付けて金銭を表す値を表示します。

差し込み印刷の側について、先に挙げた Microsoft の資料は、回避策の一つとして、メイン文書の差し込みフィールドに書式スイッチを付けて結果の書式を設定する方法を示しています。操作の詳しい手順はこの記事では扱わず、公式の資料で確かめます。

ここからは当社の整理です。表の見た目を正解の基準にする前に、通知で伝える内容を定めます。日付なら、通知日なのか対象日なのか、金額なら何の金額なのかを項目名で区別します。そのうえで、元の値と通知に載せたい表記を別に記録すると、修正する場所を考えやすくなります。

「表と違う」という報告だけでは、日付そのものが違うのか、年月日の区切りが違うのかが分かりません。金額も、値の相違と、通貨記号や桁区切りの有無を分けて扱います。見た目をそろえる作業と、内容を訂正する作業を混ぜないための整理です。

2．通知日が読みにくい場面で、照合の軸を決める

架空の更新通知で、担当者が元表と通知文を見比べ、日付の表し方と金額の区切りに違いを見つけた場面を考えます。まず元表と出力を残し、違って見える箇所を書き出します。見つけた箇所をその場で書き換える前に、参照した項目と伝える内容を確認する進め方です。

照合には、元の値、表での見え方、通知文での見え方を使います。通知日を対象日の欄と比べていないか、案内する金額と別の金額を見ていないかも、項目名に戻って確かめます。

対象元の値で確かめること表の表示形式で確かめること出力文面で確かめること・残す記録
通知日承認された通知日を参照しているか年月日の並びと区切りは何か意図した日付として読めるか。元の項目名と出力の該当箇所を残す
対象日通知日と取り違えていないか通知日と異なる表記を使う意図はあるか前後の文と合わせて対象日だと分かるか。表記の基準を残す

表の記録は、違いを説明するためのものです。金額をどう確定するかや、通知内容を承認するかは、確認担当者の判断として別に残します。

3．見た目の差と、内容の差で確認先を分ける

参照する項目や元の値に相違が見つかったものは、元データの管理担当者への確認に回します。どの資料を根拠に直すかが決まるまでは、通知文の数値だけを合わせる対応は保留にするとよいです。元データの誤りを、通知文だけの修正で覆わないためです。

一方、値と項目の対応を確認でき、違いが表し方にあると整理したものは、通知文の表記を管理する担当者と確認します。年月日の並び、通貨記号、桁区切り、単位などを、承認済みの見本と照合する進め方です。表と同じ見た目に戻すだけでなく、受け取る人に何を伝えるかを基準にします。

判断がつかない箇所には、「表示形式」と原因を先に書かず、見えた違いをそのまま残します。参照項目、元の値、通知文の該当箇所があれば、次の担当者も確認を引き継ぎやすくなります。

修正の記録には、直した場所と理由、確認した人、確認後の出力を含めます。元表を変えたのか、通知文の表記を変えたのかが追える書き方にしておくと、後で同じ通知を作り直す際の手がかりになります。

4．差し込み結果は、記号と前後の文章まで読む

Microsoftの準備手順では、通貨とパーセンテージの値を例に、差し込みフィールドの前後に適切な記号があるか確かめるよう示しています。Wordの公式手順には、レコードを切り替えながら差し込み結果を確認する流れがあります。

当社の整理では、修正後は日付や金額の部分だけでなく、その前後の言葉まで続けて読みます。何の日付か、どの金額か、単位がどこにあるかを、通知文として確認するためです。単位が見出し側にしかないものは、通知本文の中でも意味が伝わるかを見ます。

確認する見本には、表記の違いが出た項目や、補足が必要な項目を含めるとよいです。直した箇所を見直した後は、その出力が確認対象の元データから作られたものかも照合します。修正前に作った出力と、確認後に送る出力を取り違えないよう、保存名や確認記録で区別する進め方です。

確認者には「見た目が合ったか」だけでなく、「伝える内容が合ったか」を記録してもらいます。送付を保留した項目があれば、回答する担当者と再確認する対象を残し、承認済みの出力と区別して管理します。

5．AIには差の説明案を頼み、確定は人が担う

AIに任せる範囲は、照合用の材料から違いの説明案と確認待ちを作るところまでにします。元の表と通知文の写し、承認済みの表記方針を材料にし、元データの変更や送付の判断は人の作業として残す進め方です。材料に個人名や取引先名などが含まれる場合は、AIに渡してよい範囲を社内の取り決めで先に確かめ、必要な項目だけにします。

依頼文は、次のように範囲を絞れます。

目的：通知文と元表の照合メモの下書きを作る。
材料：元の値、表での表示、通知文の該当箇所、承認済みの表記方針。
出力：違いが見える箇所、確認する項目、担当者への質問案。
制約：元表と通知文は変更しない。欠けた値は補わない。
表示だけの差か内容の誤りか判断できないものは、理由とともに確認待ちに残す。

人が確かめる中心は、元の項目を取り違えていないか、説明案が材料と合うか、直した後の通知文が承認した内容になっているかです。もっともらしい原因名を付けることより、元の値と出力をたどれるメモを残すことを優先します。

6．確認表

公開・共有の前に、この表で確かめます。

確認確かめること
□通知で伝える日付と金額について、参照する項目を確定したか
□元の値と、表で見えている表示形式を分けて確認したか
□出力文面との差を、日付の並び、桁区切り、通貨記号、単位に分けて記録したか
□内容の誤りと表示上の差を区別し、判断待ちを担当者に引き継いだか
□修正した場所と理由、確認者、確認後の出力を残したか
□送付する出力が確認済みのものか、前後の文章も含めて照合したか
