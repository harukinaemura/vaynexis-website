Windowsのスタートアップでアプリの自動起動を止めるには

要点

Windows のサインイン時の自動起動を止めるには、［設定］→［アプリ］→［スタートアップ］で対象アプリを［オフ］にします。変更する対象は、仕事を始める時点で必要かどうかを担当者と整理するとよいです。操作後は、意図した状態で使い始められるかまで確かめます。

公開：2026年11月15日／情報の確認日：2026年11月15日（出典はこの記事の最後）

この記事は、Windowsのサインイン時に開くアプリを整理したい小さな会社の担当者が、スタートアップの切り替えと変更後の動作を確かめる流れをまとめたものです。

公式ページ・公式ヘルプなどの一次資料を2026年11月15日に確かめました。機能や制度は変わることがあるので、使う前に各ページで最新の状態を確認してください。法律・税務・労務の判断や、効果を約束するものではありません。

例は説明のための架空の例です。確認表や記録項目は当社の整理です。公式機関が示す様式ではありません。

  1. 自動で開く必要があるかを先に分ける
  2. 設定画面で対象の切り替えをオフにする
  3. タスク マネージャーでは影響も見られる
  4. 一覧にない場合は同じ操作を続けない
  5. 事務での使い分けを短い表にする
  6. 次の仕事の開始時に結果を確かめる
  7. 確認表
  8. 自社の事務の手順まで形にしたいとき

1．自動で開く必要があるかを先に分ける

確認日：2026年11月15日

Microsoft の日本語ヘルプの適用先は Windows 11 と Windows 10 で、この記事は Windows 11 の通常のアプリを対象にします。扱う操作は一覧上での有効・無効の切り替えまでとし、サービスやレジストリの変更は扱いません。

対象を決める際は、名前を見て用途が分かるか、担当する仕事との関係を説明できるかを先に確認するとよいです。

Microsoft は、起動時に実行するアプリによって起動時間が遅くなり、バックグラウンドの使用量が増える可能性を挙げています。「画面に出てきて煩わしい」という理由だけでまとめて変えず、仕事を始めるときの必要性を判断の軸にします。

2．設定画面で対象の切り替えをオフにする

［スタート］から［設定］、［アプリ］、［スタートアップ］の順に開きます。一覧では、変えたい対象の名前と現在の状態を見比べます。同じような名前の項目を取り違えないよう、変更前の表示をメモしておくと引き継ぎにも使えます。

一覧にある対象アプリの切り替えを［オフ］にすると、そのアプリの自動起動を止められます。対象を探す段階と、状態を変える段階を分けると、別の項目まで続けて操作する間違いを避けやすくなります。

再びサインイン時に自動起動させる場合は、対象の切り替えを［オン］にします。元の状態へ戻せるよう、変更した理由も名前と並べて残すとよいです。「使わない」とだけ書くより、「仕事の開始時には使わず、必要な業務のときに担当者が開く」と書く方が、後任者が判断しやすくなります。

3．タスク マネージャーでは影響も見られる

タスク マネージャーは、［設定］と同じスタートアップ アプリケーションの一覧を表示します。対象の表示名を控え、どちらの画面で変更したかも記録しておくと、確認時に同じ項目を追いやすくなります。

Ctrl＋Shift＋Esc キーでタスク マネージャーを開きます。左側のメニューの［スタートアップ アプリ］を選びます。対象アプリを右クリックして［無効にする］を選びます。

タスク マネージャーでは、各アプリがスタートアップに与える影響も表示されます。影響の表示は確認の手掛かりにとどめ、止めてよいかは仕事上の用途と合わせて判断するとよいです。負荷についての情報だけで、担当者が必要とする仕事まで不要と判断しないことが大切です。

4．一覧にない場合は同じ操作を続けない

Microsoft は、構成するアプリがスタートアップ一覧にない場合、エクスプローラーから構成できると案内しています。この記事の一覧上での切り替えとは別の操作になるため、ここではその手順には進みません。対象が見当たらないときは、似た名前の別項目を代わりに変更せず、表示されている名前と困っている動作を管理担当者に伝えます。

問い合わせる際は、仕事を始めるときに何が開くのか、手で開いた後のことなのかを分けて記録するとよいです。名前が分からない場合も、見えた文字をそのまま控え、推測したアプリ名で相談しないようにします。ここで必要なのは変更箇所を増やすことではなく、対象を特定するための情報です。

5．事務での使い分けを短い表にする

ここからは当社の整理です。

変更候補は、利用頻度だけでなく、仕事のどの場面で必要になるかで整理します。毎日使っていても朝すぐに開く必要があるとは限らず、利用者本人だけでは判断できない役割もあり得ます。用途が不明なものは、担当者への確認が済むまで変更を保留する運用とします。

対象の例仕事との関係変更前の整理
資料を見るための閲覧用アプリ必要な資料を扱うときに使う自分で開く運用で支障がないか確認する
朝の連絡を受けるための連絡用アプリ業務開始直後の連絡に使う自動で開く必要性を連絡担当者と確認する
用途を説明できない項目関係する仕事が分からない管理担当者が用途を確認するまで保留する

表は特定の製品を止めてよいと示すものではありません。同じ呼び方の道具でも、職場で任せている役割によって扱いは変わります。引き継ぎ用の記録では、変更した項目だけでなく、保留した理由と確認する相手も残すとよいです。

6．次の仕事の開始時に結果を確かめる

変更後の確認は、画面上の状態と、仕事を始めたときの動作に分けます。作業中の内容を保存し、次にWindowsへサインインする場面で、自分で対象を開く前に、止めたかった動作が起きるかを見ます。手で開いた後では、自動で開いたのかを区別しにくくなるためです。

次に、その日の業務に必要な連絡や作業の開始に支障がないかを確かめます。確認が済むまでは「変更済み」と「業務上の確認済み」を分けて記録するとよいです。想定と違う動作が残る場合は、さらに別の項目を無効にする前に、変更した対象と観察した動作を管理担当者へ伝えます。

後任者に渡す記録には、表示されていた名前、元の状態、変えた理由、変更後に確認したことをまとめます。業務上の支障があれば元の状態へ戻したうえで、戻した理由も残すと、同じ判断を繰り返さずに済みます。止める候補の検討と、変更後の確認を別の担当者が行う場合は、確認を依頼する相手まで決めておくとよいです。

端末を使い始めるときの事務の手間を洗い出すなら、毎回行う準備と人が判断する部分を分け、AI 活用を考える際の作業整理につなげることもできます。

7．確認表

公開・共有の前に、この表で確かめます。

確認確かめること
□対象の名前と、仕事での用途を確認したか
□仕事を始める時点で自動起動が必要か検討したか
□変更前の状態と、変えた理由を記録したか
□対象を取り違えずに変更し、変更後の表示を確認したか
□改めて使い始めたときの動作と、業務への支障の有無を確認したか
□用途が不明な項目や、想定と違う動作の確認先を整理したか
