Excelで社内・外部データを結合する前のプライバシー設定確認

要点

Power Queryで社内・外部データを結合する前は、データソースのプライバシーレベルと、結合時にその分類を適用するオプションを分けて確かめます。取込元に含まれる情報と閲覧を認める範囲を整理し、判断が付かないものは管理担当者へ確認してから進める流れにします。

公開：2026年11月4日／情報の確認日：2026年11月4日（出典はこの記事の最後）

この記事は、社内の表と外部の公開データをExcelで結合したい小さな会社の事務担当者が、取込元ごとの分類と結合時の設定を確かめる流れをまとめたものです。

公式ページ・公式ヘルプなどの一次資料を2026年11月4日に確かめました。機能や制度は変わることがあるので、使う前に各ページで最新の状態を確認してください。法律・税務・労務の判断や、効果を約束するものではありません。

例は説明のための架空の例です。確認表や作例は、当社の考えをまとめたもので、公式の機関が示しているものではありません。

  1. 結合の前に、情報を見せてよい範囲を整理する
  2. データソースごとの分類を開いて確かめる
  3. 結合時に分類へ従う設定も見る
  4. 架空の照合例では、分類の前に項目を洗い出す
  5. 警告や停止があれば、対象と設定へ戻る
  6. 確認表
  7. 自社の事務の手順まで形にしたいとき

1．結合の前に、情報を見せてよい範囲を整理する

確認日：2026年11月4日。

公式ヘルプは、プライバシーレベルの誤設定によって機密データが信頼できる環境の外へ漏れる可能性を示しています。取込元を確認する目的は、表を表示できるようにすることだけではなく、含まれる情報をどこまで扱ってよいかを確かめることです。

機密性の高いデータを含むデータソースは［プライベート］に分類するのが公式の案内です。［組織］は表示を信頼できるユーザーグループに制限する分類で、［パブリック］は誰もがデータを見られる分類です。

ここでは、既存の接続があるデスクトップ版のブックについて、設定を確認する操作を扱います。Mac版のExcelでは、現在プライバシーレベルがサポートされていないため、同じ操作を前提にしません。

2．データソースごとの分類を開いて確かめる

まず、作業対象のブックと取込元の場所を照合します。似た名前のファイルを取り違えないよう、担当者へ渡された一覧と、これから確認する対象を対応させておくとよいです。

Excelの［データ］から［データの取得］、［データ ソース設定］へ進みます。一覧で対象のデータソースを選び、［アクセス許可の編集］を開きます。［プライバシー レベル］の選択欄で、現在の分類を確認して変更できます。

この段階で、表示された分類と、情報を見せてよい範囲についての社内判断を突き合わせます。社内に置いた表、外から取り込んだ表という呼び方だけで判断を済ませず、管理担当者が確認できるよう、含まれる項目と用途も控えます。

変更する場合は［OK］を選び、［閉じる］で画面を閉じます。確認の仕上げとして、同じデータソースの［アクセス許可の編集］を開き直し、選択したプライバシーレベルを見ます。

取込元が複数ある場合は、確認を終えた対象と、判断を待っている対象を分けて記録します。変更した内容を記憶だけに頼らず、元の分類と変更後の分類、判断した担当者を残す形にすると、引き継ぎ先も経緯をたどれます。

3．結合時に分類へ従う設定も見る

続いて、［データ］から［データの取得］、［クエリ オプション］を開きます。［クエリ オプション］には、［グローバル］の［プライバシー］と、［現在のブック］の［プライバシー］があります。

［グローバル］には、常に各ソースの設定に従う選択肢や、各ファイルの設定に従う選択肢があります。確認したいブックだけを見る前に、全体でどの扱いになっているかを把握する流れです。管理担当者が全体の設定を決めている場合は、その方針と影響する範囲を確認してから変更を検討します。

［現在のブック］では、各ソースのプライバシーレベル設定に従ってデータを結合する選択肢を確認します。プライバシーレベルを無視する設定は、承認されていない人への機密データの開示につながる可能性があります。

ここでの作業記録には、確認した範囲も添えます。分類を確かめたとだけ書くより、取込元の分類を見たのか、結合時の扱いを見たのかを区別した方が、未確認の箇所を追いやすくなります。会社全体の運用に関わる変更は、事務担当者だけで進めず管理担当者と相談する流れです。

4．架空の照合例では、分類の前に項目を洗い出す

ここからは当社の整理です。

社内で管理する配送先の表に、外部の公開地域一覧を結び付ける場面を考えます。結果を作る担当者が、分類を決める担当者へ渡す確認材料の例です。

取込元含まれる項目の例分類を判断する前の確認
社内の配送先表担当者名、届け先、地域名各項目を見せてよい範囲を管理担当者へ確認する
外部の公開地域一覧地域名、地域の区分参照する一覧の公開範囲と内容を確認する
照合して作る表配送先と地域の区分誰へ渡す予定の表かを先に控える

公開されている一覧を使う場面でも、社内の表に含まれる項目の扱いは別に確認します。判断に必要な情報がそろっていなければ、設定変更を保留し、不明な項目と確認先を記録する進め方です。担当者名を含まない見本を用意し、結び付ける項目の対応を先に確かめておくと、操作の問題と情報の扱いの判断を切り分けられます。

5．警告や停止があれば、対象と設定へ戻る

Power Query の公式資料によると、未設定の取込元がある場合や分類が異なる場合、Power Queryはデータのプライバシー情報を求める警告を表示します。制限の厳しい分離レベルは情報交換をブロックする一方で、機能や処理性能に影響する可能性があります。

警告を見たら、画面の文言と、そのとき扱っていた取込元を控えます。結合を通すための変更を重ねる前に、未設定の対象があるか、社内で確認した内容と表示が合うかを見直す順序にします。判断が付かないまま分類をそろえず、管理担当者が元の状態を確かめられるよう、変更した箇所も併記するとよいです。

設定の確認を終えた後は、作成された表の列、照合した項目、想定外の行の増減を元の表と見比べます。結合できたことと、業務で使う結果が合っていることは分けて確認し、引き継ぎには設定の確認状況と結果の照合状況を残します。

6．確認表

公開・共有の前に、この表で確かめます。

確認確かめること
□結合する取込元と、その中に含まれる項目を洗い出したか
□情報を見せてよい範囲を管理担当者へ確認したか
□各取込元の分類を開き、社内の判断と照合したか
□分類と、結合時の扱いを決める設定を分けて確認したか
□変更後に設定を開き直し、確認した範囲と内容を控えたか
□警告の内容と未解決の確認先を引き継ぎに残したか
□作成された表を元の表と照合したか
