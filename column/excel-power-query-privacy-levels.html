Excelのプライバシーレベルとは？Power Queryの設定場所と無視するときの注意

要点

プライバシーレベルは、データソースごとに、ほかのデータソースからどれだけ分離するかを決める分類です。Excel では［データ］→［データの取得］→［データ ソース設定］で対象を選び、［アクセス許可の編集］の［プライバシー レベル］で「なし・プライベート・組織・パブリック」から選びます。機密性の高いデータを含むソースは［プライベート］にするよう案内されています。結合のときにこの分類に従うか無視するかは、別の画面の［クエリ オプション］で決めます。

公開：2026年11月4日／更新：2026年11月19日／情報の確認日：2026年11月18日（出典はこの記事の最後）

社内の表と外部の公開データを Power Query でつなごうとして、プライバシーレベルの警告やエラーが出ることがあります。プライバシーレベルとは何か、どこで変えるか、無視する設定を選んでよいのはどんなときかを、Microsoft のサポートと Learn の資料で確かめます。

公式ページ・公式ヘルプなどの一次資料を2026年11月18日に確かめました。機能や画面は変わることがあるので、使う前に各ページで最新の状態を確認してください。法律・税務・労務の判断や、効果を約束するものではありません。

照合の例は説明のための架空の例です。表の整理と確認表は当社のもので、Microsoft が示しているものではありません。

1．プライバシーレベルとは：データソースを4つに分ける設定

確認日：2026年11月18日

Microsoft Learn の説明では、プライバシー レベルは、1 つのデータ ソースを他のデータ ソースから分離する度合いを決める分離レベルです。制限の厳しい分離レベルではデータ ソース間の情報交換がブロックされますが、機能とパフォーマンスが低下する可能性があります。Microsoft サポートでは、プライバシー レベルを誤って設定すると、機密データが信頼できる環境の外部に漏洩する可能性があるとされています。

プライバシー レベル意味（Microsoft の説明の要約）資料にある例
なしプライバシー設定がない。テストとパフォーマンス上の理由から、制御された開発環境で使うもの（開発環境のデータ ソース）
プライベート機密情報を含み、表示は承認されたユーザーに制限される。他のデータ ソースから完全に分離従業員レビューを含むブック など
組織表示を信頼できるユーザー グループに制限。パブリックのデータ ソースからは分離イントラネットの SharePoint サイト上の Word 文書
パブリックすべてのユーザーがデータを見られる。ファイル、インターネット データ ソース、ブック データだけがパブリックにできるWikipedia のページのデータ

どちらの資料でも、機密性の高いデータを含むデータ ソースは［プライベート］に設定するよう案内されています。社員名簿や取引先の連絡先のような表を、公開データと同じ扱いにしないための設定だと考えると分かりやすくなります。なお、Microsoft Learn の注では、現在、Excel on the Mac ではプライバシー レベルはサポートされていないとされています。

2．設定する場所：［データ ソース設定］→［アクセス許可の編集］

Microsoft サポートの手順では、Excel で［データ］→［データの取得］→［データ ソース設定］を選ぶと［データ ソース設定］ダイアログ ボックスが開きます。Power Query エディターからは［ファイル］→［オプションと設定］→［データ ソース設定］です。

  1. ［データ ソース設定］で対象のデータ ソースを選び、［アクセス許可の編集］を選択します。
  2. ［プライバシー レベル］のドロップダウン リストから、なし・プライベート・組織・パブリックのいずれかを選びます。
  3. ［OK］を選択します。

変えたあとは、同じデータ ソースの［アクセス許可の編集］を開き直し、選んだレベルになっているかを見ます。取込元が複数ある場合は、確認を終えたものと判断を待っているものを分けて控えます。元のレベル、変えたあとのレベル、判断した人を残しておくと、引き継いだ人が経緯をたどれます。どのレベルにするかは表の中身で決まるので、事務の担当者だけで決めかねる表は、情報の管理を担当する人に確かめてから変えます。

3．結合のときに従うか無視するか：［クエリ オプション］

データ ソースの分類とは別に、結合のときにその分類を使うかどうかを決める設定があります。Excel では［データ］→［データの取得］→［クエリ オプション］を開き、左側の［グローバル］または［現在のブック］の［プライバシー］で選びます。

画面選択肢資料にある注意
グローバル常に各ソースのプライバシー レベル設定に従ってデータを結合する／各ファイルのプライバシー レベル設定に従ってデータを結合する／常にプライバシー レベルを無視する従う設定はパフォーマンスと機能が低下する可能性がある。無視する設定はマージしたデータのプライバシーを確保できない
現在のブック各ソースのプライバシー レベル設定に従ってデータを結合する／プライバシー レベルを無視する同上

プライバシー レベルを無視するオプションは「高速結合」とも呼ばれます。Microsoft サポートは、［プライバシー レベルを無視して、パフォーマンスを向上する］を選んで高速結合を有効にすると、承認されていないユーザーに機密データが開示される可能性があるとし、データ ソースに機密データが含まれていないことが確証できる場合を除き、高速結合を有効にしないよう注意しています。既定では有効になっていません。エラーを消すためだけに「無視する」を選ぶのではなく、先に各ソースの分類を見直す順にします。

4．プライバシーレベルの警告と Formula.Firewall のエラー

Microsoft Learn によると、複数のソースのデータを結合するときに、いずれかのソースのプライバシー レベルが設定されていない場合や、プライバシー レベルが異なる場合は、Power Query でデータのプライバシー情報が必要であるという警告が表示されます。ボタンから［プライバシー レベル］ダイアログを開き、まだレベルのないソースに設定します。

レベルが異なるソースどうしは、結合が止まることがあります。Learn には、ブックのデータを［プライベート］、SQL Server のデータを［組織］に設定してマージすると、プライベートの方が組織より制限が厳しいため、Power Query はデータ ソース間の情報交換をブロックするという例が載っています。

そのときに出るのが、「Formula.Firewall: Query 'Query1' (step 'Source') is accessing data sources that have privacy levels which cannot be used together. Please rebuild this data combination.」のようなエラーです。Learn の「データ プライバシー ファイアウォールの舞台裏」では、このエラーは Power Query のデータ プライバシー ファイアウォールの結果で、ファイアウォールの目的は、Power Query がソース間で意図せずにデータを漏えいするのを防ぐことだと説明されています。参照しているクエリの組み方が原因で出る「references other queries or steps」の形のエラーもあります。どちらも、分類と組み方を見直すための知らせとして扱います。

5．分類を決める前に、取込元の項目を洗い出す

社内で管理する配送先の表に、外部の公開地域一覧を結び付ける架空の場面で、分類を決める前に洗い出す項目を並べます。

取込元含まれる項目の例分類を決める前に確かめること
社内の配送先表担当者名、届け先、地域名各項目を見せてよい範囲を管理担当者へ確かめる
外部の公開地域一覧地域名、地域の区分一覧の公開の範囲と内容
照合して作る表配送先と地域の区分誰へ渡す予定の表か

公開されている一覧を使う場合でも、社内の表に含まれる項目の扱いは別に考えます。判断に必要な情報がそろわなければ、設定は変えずに、分からない項目と確認先を記録しておきます。担当者名を含まない見本で結び付ける列の対応を先に確かめておくと、操作の問題と情報の扱いの判断を切り分けられます。

結合できたら、作られた表の列、照合した項目、想定外の行の増減を元の表と見比べます。結合できたことと、業務で使う結果が合っていることは別に確かめ、引き継ぎには設定の確認の状況と結果の照合の状況を残します。

6．確認表

公開・共有の前に、この表で確かめます。

確認確かめること
□結合する取込元と、その中に含まれる項目を洗い出したか
□機密性の高いデータを含むソースを［プライベート］にしたか（決めかねるものは管理担当者に確かめたか）
□［データ ソース設定］→［アクセス許可の編集］で、各ソースのレベルを開き直して確かめたか
□［クエリ オプション］の［グローバル］と［現在のブック］の［プライバシー］を分けて見たか
□［プライバシー レベルを無視する］（高速結合）を、機密データが無いと確証できないまま選んでいないか
□警告や Formula.Firewall のエラーの文言と、そのとき扱っていた取込元を控えたか
□作られた表を元の表と照らし、行の増減と列を確かめたか
