Excelの目次から目的のシートや記入欄へ移動するには

要点

目次から記入欄へ移動する入口にはハイパーリンクを使い、関数で作る場合は、現在のブック内の別の場所へ移動できるHYPERLINK関数を使えます。目次を整えるときは、項目名だけでなく、到着後に何を記入する場所なのかまで決めておくとよいです。

公開：2026年11月6日／情報の確認日：2026年11月6日（出典はこの記事の最後）

この記事は、シートが増えたExcelのブックに目次を作りたい小さな会社の担当者が、リンクの挿入とHYPERLINK関数で目的のシートや記入欄へ移動する入口を作り、行き先を確かめる流れをまとめたものです。

公式ページ・公式ヘルプなどの一次資料を2026年11月6日に確かめました。機能や制度は変わることがあるので、使う前に各ページで最新の状態を確認してください。法律・税務・労務の判断や、効果を約束するものではありません。

例は説明のための架空の例です。確認表や作例は、当社の考えをまとめたもので、公式の機関が示しているものではありません。

  1. 目次のセルから、同じブック内の移動先を指定する
  2. 目次には「何をする場所か」を載せる
  3. 到着したシートだけでなく、欄の用途まで確かめる
  4. 表示名と行き先を分けて引き継ぐ
  5. 確認表
  6. 自社の事務の手順まで形にしたいとき

1．目次のセルから、同じブック内の移動先を指定する

ここで扱う画面操作は、公式ヘルプ「Excel でリンクを操作する」の適用先として示されている Excel for Microsoft 365、Excel 2024、Excel 2021、Excel 2019、Excel 2016 の手順です。Mac 版と Excel for the web の画面は、この記事では扱いません。

入口を選び、移動先を設定する

先に、目次に載せる項目と行き先の欄を対応させておきます。表の見出しを読みたいのか、記入を始めたいのかを区別しておくと、指定する場所を決めやすくなります。

  • 目次の入口にするセルを選び、Ctrl＋Kで［ハイパーリンクの挿入］ダイアログを開きます。
  • ［リンク先］では、同じブック内へ移るための［このドキュメント内に場所］を選びます。
  • ［セル参照］の一覧で移動先のシートを選び、［セル参照を入力してください］に目的のセルの参照を入力して、［OK］で確定します。

設定後は、目次の入口から目的の欄へ到着するかを確かめます。項目を増やす前に、入口と行き先の対応を見直しておくとよいです。

関数で入口を作る場合

HYPERLINK 関数の書式は HYPERLINK(リンク先, [別名]) です。公式ヘルプの例では、January がブックの別のワークシートの場合に、リンク先を「[Book1.xlsx]January!A10」のようにブックの名前とワークシートの名前の両方を含めて書き、そのシートのセル A10 へ移動します。別名には、セルに表示する文字列または数値を指定します。

目次では、この別名を項目名にすると、表示名と行き先を1つのセルで組にできます。例の Book1.xlsx と January は説明用の名前なので、自分のブックとシートの名前に置き換えたうえで、目次のセルから目的の欄へ移動するかを確かめます。

2．目次には「何をする場所か」を載せる

ここからは当社の整理です。

目次を作る際は、すべての表を細かく並べるよりも、読む人が探しそうな作業を先に選びます。閲覧の入口と記入の入口を分けておけば、着いた場所で次に何をするかも伝えられます。

目次に載せる項目の例行き先に選ぶ場所の例到着後に確かめること
申請内容を記入する申請用の表の記入開始欄説明を読む場所と記入欄を取り違えていないか
費用の内訳を見る内訳の表の見出し対象となる内容が見出しから分かるか
記入上の注意を読む注意事項の説明の冒頭記入前に読む説明へ到着しているか

「申請」「内訳」「注意」のような短い語だけでは、何をする入口なのかが伝わりにくいことがあります。「記入する」「見る」「読む」のように、行き先で行う作業を添える書き方です。

行き先を選ぶ際は、空いている欄だからという理由で決めず、実際に作業を始める場所と照らし合わせます。表を読むための入口なら見出し、記入の入口なら対象の欄というように、用途に合わせて整理するとよいです。

3．到着したシートだけでなく、欄の用途まで確かめる

移動できたことと、意図した場所に着いたことは分けて確かめます。目的の用紙が開いていても、説明の末尾や、別の作業で使う欄に着いていないかを見るためです。

確認は目次の入口から始める

確認の際は、行き先を直接開くだけで終えず、利用する人と同じように目次の入口をたどります。そのうえで、表示された見出し、欄の用途、目次の項目名を突き合わせます。見慣れた用紙であっても、項目名の意味と到着先の説明が対応しているかを確かめるとよいです。

引き継ぎ前には、作成者以外の人にも目次を読んでもらう方法があります。どの入口を選ぶか迷った場合は、項目名を見直す手がかりになります。操作を口頭で補わなくても行き先を選べるか、到着後に何をするか分かるかを確認します。

表の構成を変えた後にも確認する

用紙の見出しや欄の配置を変えた後は、目次の項目と移動先を再確認する運用にします。以前と同じように移動できるかだけでなく、移動先が今も目的の欄なのかを見るためです。

到着先の用途が変わっている場合は、入口の名称と行き先の対応を見直します。目次に載せた項目が今も必要かも含めて整理すると、使わなくなった入口を残すかどうか判断しやすくなります。

4．表示名と行き先を分けて引き継ぐ

Microsoft のアクセシビリティの案内では、リンクはリンク先の情報を明確かつ正確に伝える必要があるとしています。

引き継ぐ際は、目次で見せる言葉と、その言葉が指す行き先を組にして残すとよいです。目次だけを見れば作業を選べ、修正を担当する人は対応する欄を調べられる形にします。利用する人に必要な案内と、保守する人に必要な情報を意識しておくためです。

入口の名称を整えた後も、行き先の確認は別に行います。名称が分かりやすいことと、目的の欄へ到着することの両方を確認できてから、引き継ぎ用として扱うとよいです。

関数で入口を作っている場合、HYPERLINK 関数のヘルプでは、リンク先で指定したジャンプが存在しない、または移動できないと、セルをクリックしたときにエラーが表示されるとしています。

エラーの有無だけを完了の目印にせず、到着した欄で予定した作業を始められるかを確かめます。移動先を直す場合も、先に意図した行き先を整理し、修正後に入口からたどり直す流れにしておくと、引き継ぐ人と確認する範囲をそろえられます。

5．確認表

公開・共有の前に、この表で確かめます。

確認確かめること
□目次に載せる作業と、その行き先の欄を対応させたか
□閲覧の入口と記入の入口を区別したか
□項目名だけで、行き先で行う作業が分かるかを確認したか
□目次の入口から、意図した用紙と欄へ移動するかを確認したか
□表の構成を変えた後、移動先の用途を再確認したか
□引き継ぐ人と、入口の名称・行き先・確認する範囲を共有したか
