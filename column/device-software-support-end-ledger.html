社内の端末とソフトのサポート終了を定期確認する台帳と進め方

要点

社内の端末とソフトのサポート終了は、使用中の対象を台帳にまとめ、提供元の公式情報で期限を照合し、確認日と次に確認する時期を残す流れで管理します。期限を調べる担当者に加え、更改の判断を受ける責任者と、作業の完了を確かめる担当者まで決めておくと、調査から対応へつなげやすくなります。

公開：2026年11月4日／情報の確認日：2026年11月4日（出典はこの記事の最後）

この記事は、社内の端末とソフトのサポート期限を定期的に確かめたい小さな会社の担当者が、台帳への記録から提供元の公式情報との照合、更改の判断の引き継ぎまでを確かめる流れをまとめたものです。

公式ページ・公式ヘルプなどの一次資料を2026年11月4日に確かめました。機能や制度は変わることがあるので、使う前に各ページで最新の状態を確認してください。法律・税務・労務の判断や、効果を約束するものではありません。

例は説明のための架空の例です。確認表や作例は、当社の考えをまとめたもので、公式の機関が示しているものではありません。

  1. 公式資料で、期限確認と更改の項目を押さえる
  2. 製品名の先にある、版と適用対象を照合する
  3. 台帳では、機器とソフトを分けて記録する
  4. 確認の予定を、対応を始める時期につなげる
  5. 期限が不明な対象と、更改の判断を引き継ぐ
  6. 確認表
  7. 自社の事務の手順まで形にしたいとき

1．公式資料で、期限確認と更改の項目を押さえる

IPAの「中小企業の情報セキュリティ対策ガイドライン 第4.0版」は、ハードウェア・OS・ソフトウェアのサポート期限を定期的に確認するよう示しています。 冊子の34頁には、サポート期限の切れたOS及びソフトウェアの利用停止及び更改の項目があります。

2．製品名の先にある、版と適用対象を照合する

Windows 11 Home と Pro の公式ページは、Home と Pro を適用対象のエディションに含めています。 Windows 11 Enterprise and Education の公式ページは、Education、Enterprise、Enterprise multi-session を適用対象としています。 Home と Pro の英語版ページには、サポート日付は太平洋時間で表示されると記載されています。

ここからは当社の整理です。使用中の製品名、版、更新状況を控えてから、該当する提供元のページへ進みます。検索で見つけた終了日の隣にある対象の説明まで読み、自社で使っているものと一致するかを確認する順序です。

製品全体の状態と、使っている版の期限を分けて記録すると、確認箇所を取り違えにくくなります。日付を転記する際は、掲載されている時刻や時間帯の注記も一緒に残すとよいです。対象や日付の意味が読み取れない箇所は、問い合わせる内容として切り分けます。

3．台帳では、機器とソフトを分けて記録する

パソコンの購入日や保守契約の書類だけを確認先にせず、現に使っている機器と、その上で動くソフトの情報を並べて整理します。機器側とソフト側の期限を別々に書ける形にしておくと、何について調べ終えたのかを区別できます。

台帳には、管理対象を識別する名前、設置場所、利用者、提供元、型番や版、確認した公式ページ、期限の種類と日付、確認日、次回確認予定、対応担当者を持たせます。項目を埋める担当者と、対象の選び方を確認する担当者を決め、元の資料までたどれるようにします。

次の表は、記録と役割の組み合わせを示す見本です。

きっかけ誰が用意するもの記録して渡すこと
機器やソフトを追加したとき購入・導入の担当者型番や版が分かる情報、保守関係の書類利用場所、利用者、期限の確認先
定期確認の予定が来たとき台帳の担当者前回の記録、提供元の公式情報対象との一致、期限、確認日、次回確認予定
更改の準備が必要になったとき業務の責任者と管理担当者使用中の業務、移行先の候補、作業上の制約決める相手、対応方針、準備の担当者
入れ替えや利用終了を終えたとき作業担当者と確認担当者作業の記録、入れ替え後の対象情報完了の確認、旧対象の扱い、台帳の更新

同じ機器に関係するソフトは、機器の管理名を使ってひも付けます。利用者の記憶に頼らず、後任者が対象を見つけられる書き方にそろえることが目的です。新しい機器へ入れ替えた際も、古い対象の行を消すだけで終わらせず、扱いの変更を記録します。

4．確認の予定を、対応を始める時期につなげる

期限を見つけたあとに、対応を検討する相手へ渡すところまで用意しておきます。台帳に日付を転記する作業と、使っている業務をどう移すかの検討をつなぐことが大切です。調べた対象がそのまま残ってしまわないよう、確認結果に担当者と次の行動を添えます。

定期確認は、担当者の予定表や共有の作業一覧に入れます。確認する間隔は、対象の数や変更の多さ、更改に必要な準備を踏まえて社内で決めます。導入・入れ替え・契約変更の連絡を受けた際にも台帳を見直す運用にすると、予定の合間に変わった対象を拾いやすくなります。

次回の確認予定と、更改に向けた準備の着手予定は分けて持ちます。利用部門との調整、移行先の動作確認、購入の手続きなどを洗い出し、終了日から準備をさかのぼって考える流れです。調査を担当する人だけで抱えず、業務側の責任者へ早めに渡せる形にします。

確認結果は「前回と同じ」「変更あり」「照合が必要」など、理由が分かる状態で残します。前回と変わらなくても確認日を更新し、変わった内容は古い記録と比べられるように保存します。問い合わせ中の対象には回答を確認する予定を置き、回答待ちのまま次の点検へ持ち越さない仕組みを考えます。

5．期限が不明な対象と、更改の判断を引き継ぐ

公式情報と使用中の対象を結び付けられないときは、型番や版、利用している業務、参照したページ、読み取れなかった箇所をまとめて提供元や保守の窓口へ問い合わせます。回答についても、対象と期限の種類が分かる形で台帳に残します。

期限切れや期限が近い対象が見つかった際は、業務の責任者と情報管理の担当者へ共有し、更改や利用終了の方針を検討します。使い続けられるかを事務担当者だけで判断せず、移行の方法や停止に伴う影響は、保守を担当する事業者や専門家に確認する流れです。

管理の区切りは、問い合わせの送信や購入の発注ではなく、対象の扱いが決まり、作業後の状態を確認して台帳を更新したところに置きます。保留する対象も、理由、判断する相手、次に確認する予定を残すと、担当者が交代したあとも続きを進めやすくなります。

6．確認表

公開・共有の前に、この表で確かめます。

確認確かめること
□使用中の機器とソフトを洗い出し、型番や版、利用場所を記録したか
□公式情報の適用対象と、社内で使う対象を照合したか
□期限の種類、日付の注記、確認したページと確認日を記録したか
□次回確認の予定と、更改の準備を始める予定を分けて設定したか
□照合できない対象について、問い合わせ先と回答を確認する予定を記録したか
□対応方針を判断する責任者と、作業後に確認する担当者を決定したか
□入れ替えや利用終了後の状態を確認し、台帳を更新したか
