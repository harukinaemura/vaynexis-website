Excelで対応待ちの行だけを別シートへ自動表示するには

要点

ExcelのFILTER関数を使うと、状態の列を条件にして、対応待ちの行を抽出できます。元の表と確認用の一覧を同じファイル内で分け、抽出する範囲と状態を調べる範囲をそろえて組み立てます。日々の更新先も先に決めておくとよいです。

公開：2026年11月4日／情報の確認日：2026年11月4日（出典はこの記事の最後）

この記事は、Excelの表から対応待ちの行だけを別シートに表示したい小さな会社の担当者が、FILTER関数の組み立てと表示の確かめ方を整理する流れをまとめたものです。

公式ページ・公式ヘルプなどの一次資料を2026年11月4日に確かめました。機能や制度は変わることがあるので、使う前に各ページで最新の状態を確認してください。法律・税務・労務の判断や、効果を約束するものではありません。

例は説明のための架空の例です。確認表や作例は、当社の考えをまとめたもので、公式の機関が示しているものではありません。

  1. 使える版と表示先を先に確かめる
  2. 小さな表から抽出する数式を組む
  3. 行を追加する表は参照の持ち方を変える
  4. 表示が出ないときは置き場所と再計算を見る
  5. 引き継ぐ前に表示の入れ替わりを照合する
  6. 確認表
  7. 自社の事務の手順まで形にしたいとき

1．使える版と表示先を先に確かめる

FILTER 関数の日本語のヘルプでは、適用先として Excel for Microsoft 365、Excel 2024、Excel 2021 と、それぞれの Mac 版などが挙げられています。この記事は Windows 版の画面の名前で書きます。自分の画面と照合する際は、利用している版も引き継ぎのメモに残します。

別シートの範囲は、シート名と感嘆符をセル参照の前に付けて指定できます。まずは同じファイルの中に、入力を続ける「元表」と、読むための「対応待ち一覧」を用意する構成にします。

数式を入力してEnterキーで確定すると抽出結果が必要な大きさに広がるため、表示先の下と右に空きを用意します。確認用の一覧の近くに別のメモを詰め込まず、元の表とは役割を分けておくと扱いやすくなります。

2．小さな表から抽出する数式を組む

例では「元表」の先頭行に見出しを置き、その下に次の内容を入力する想定です。列は左から「管理名」「内容」「状態」とします。

管理名内容状態
依頼あ資料の送付対応待ち
依頼い内容の確認完了
依頼う日程の連絡対応待ち

FILTERの引数は、抽出対象、条件、該当データがない場合に返す値の順に指定します。次は公式の構文を、この例の配置に当てはめた数式です。表の内容やセル位置は説明用に決めたもので、公式資料の掲載例そのものではありません。

表示用のシートでは、見出しを元の表と同じ順に置き、その下の左端に数式を置く構成にします。

=FILTER('元表'!A2:C4,'元表'!C2:C4="対応待ち","該当なし")

この式で表す処理は「元の表の明細全体から、状態が対応待ちの行を表示する」です。例では、資料の送付と日程の連絡を確認する一覧として使う想定です。

条件に当てはまるデータがない場合の表示は、末尾の引数で指定できます。例の「該当なし」は、空欄のままだと処理の結果かどうか迷いそうな場面を考えて付けた文言です。文字列を変える際も、引き継ぐ人に意味が伝わる表現を選びます。

行を抽出する場合は、抽出対象と条件を調べる範囲の高さをそろえます。見出しを明細に混ぜず、同じ行どうしを対応させる考え方が大切です。

3．行を追加する表は参照の持ち方を変える

先ほどの式は、例として指定した範囲を対象にしています。日々明細を増やす運用では、新しい明細まで対象に含まれるかも確認する必要があります。

元の表をテーブルにする操作は、データ内のセルや範囲を選び、［ホーム］から［テーブルとして書式］を選ぶ流れです。実際に使う範囲と見出しを確認してから進めます。

テーブル名は、テーブル内のセルを選び、［テーブル デザイン］の［テーブル名］ボックスで変更できます。この例では名前を「対応表」とする想定です。

テーブル名と列名を使う構造化参照では、参照の中の名前が、テーブルにデータを追加または削除するたびに調整されます。その参照方法を先ほどの抽出条件と組み合わせるなら、式は次の形になります。

=FILTER(対応表,対応表[状態]="対応待ち","該当なし")

こちらも、公式の構文を説明用の表名と列名に当てはめた例です。入力側で増やす行が、名前を付けた表の範囲に含まれているかを照合します。

結果を広げる数式は、テーブルの内部ではなく、テーブル外の通常のセルに置きます。入力側の表を整える操作と、表示側に式を置く操作を分けて進めるとよいです。

4．表示が出ないときは置き場所と再計算を見る

表示先がほかのデータでふさがっている場合は、#SPILL!エラーが返されます。周辺の入力を調べるときは、その内容が業務上必要なものかも確かめ、むやみに消さずに退避先を決めます。

結果の範囲で編集できるのは、数式がある先頭のセルだけです。運用では、状態の変更先を元の表に統一し、表示用の一覧を確認するための場所として案内するとよいです。

計算方法を調べる場所は、［ファイル］→［オプション］→［数式］です。設定を見直す前に、参照している元の表が意図したものかも見比べます。

［自動］は、値や数式などの変更に応じて依存する数式を再計算する設定です。計算設定の変更は、デスクトップアプリで開いているすべてのブックに影響します。

5．引き継ぐ前に表示の入れ替わりを照合する

ここからは当社の整理です。

元の表と表示用の一覧を並べ、対応待ちとして扱う明細が一致しているかを見比べます。表示件数だけで判断せず、内容と状態の組み合わせまで確認する方法です。

確認用のデータでは、対応待ちの状態を完了に変える、完了の状態を対応待ちに戻す、該当する明細をなくす、といった変更を順に試します。新しい明細を末尾に加える場面も含めると、運用中の増減を想定した点検になります。どの変更で何が表示される想定なのか、先に短くメモしてから比べるとよいです。

引き継ぎのメモには、元の表の場所、状態の表記、変更を入力する場所、表示が合わないときの確認先を残します。抽出結果の表示までを扱い、元の表を更新する自動処理や前回との差分を記録する仕組みは対象にしません。

6．確認表

公開・共有の前に、この表で確かめます。

確認確かめること
□元の表と表示用の一覧を分け、更新する場所を決めたか
□抽出対象の明細と状態を調べる列の行範囲をそろえたか
□対応待ちとして扱う表記を統一したか
□表示先の下と右に、結果を置くための空きを用意したか
□状態の変更と明細の追加が、想定した表示になるかを照合したか
□該当する明細がない場合の表示を確認したか
□利用する版と、表示が合わない場合の確認先を引き継いだか
