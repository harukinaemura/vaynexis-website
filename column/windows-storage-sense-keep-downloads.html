Windowsのストレージセンサーでダウンロードを消さない設定

要点

ダウンロードした書類を自動削除させないには、ストレージ センサーでダウンロード フォルダーを削除対象にしない設定にします。設定を見直した後は、残したい書類の有無と、選択した値を分けて確認し、担当者へ引き継げる形で記録するとよいです。

公開：2026年11月16日／情報の確認日：2026年11月15日（出典はこの記事の最後）

この記事は、ダウンロードした書類をストレージセンサーの自動削除から外したい小さな会社の担当者が、Windows の保持設定と利用者ごとの対象範囲を確かめる流れをまとめたものです。

公式ページ・公式ヘルプなどの一次資料を2026年11月15日に確かめました。機能や制度は変わることがあるので、使う前に各ページで最新の状態を確認してください。法律・税務・労務の判断や、効果を約束するものではありません。

例は説明のための架空の例です。確認表や記録項目は当社の整理です。公式機関が示す様式ではありません。

  1. ダウンロードの削除設定を開いて選択値を見る
  2. 実行する頻度と、削除の対象になる条件は別です
  3. 共有端末は利用者の設定と管理側の設定を分けて確認する
  4. 事務の記録は「残すもの」と「見た状態」を短くそろえる
  5. 設定を確認した後は、書類を置く流れを見直す
  6. 確認表
  7. 自社の事務の手順まで形にしたいとき

1．ダウンロードの削除設定を開いて選択値を見る

確認日：2026-11-15

Microsoft の日本語ヘルプの適用先は Windows 11 と Windows 10 で、この記事では Windows 11 のダウンロードの保持設定を扱います。画面の表記は Windows の版や更新状況によって異なることがあります。［スタート］から［設定］→［システム］→［ストレージ］の順に進み、［ストレージ センサー］を選択します。スイッチがオンかオフかだけを見て終えず、どのファイルを削除する設定になっているかまで見ます。

日本マイクロソフトのサポートチームが2023年1月19日に公開した解説では、ダウンロードの削除設定の既定値を「許可しない」としています。残したい場合は、削除を許可しない選択になっているかを確認します。期間が選ばれている場合は、削除を許可しない状態へ変更します。項目の名前と現在の選択値を組にして読み取り、変更前の状態も控えておくとよいです。

変更する前には、対象の欄が受け取った書類の保存先に対応しているかを見ます。近くの欄の値を変えた後で「自動削除を止めた」と記録せず、何を対象から外したのかが分かる形にするとよいです。

なお、ここで扱うのは書類を残すための保持設定です。すでに消えた書類を戻す操作や、別の保存先との同期の調整は扱いません。

2．実行する頻度と、削除の対象になる条件は別です

［ストレージ センサーの実行］では、サインインしてオンラインになっているときに実行する頻度を選びます。これは処理をいつ動かすかという設定です。残したい書類の扱いを確認する際は、実行する間隔と、削除してよいと指定した条件を分けて読みます。

同サポートチームの2023年公開の解説では、削除対象になるのは、ファイルの更新日時とアクセス日時が、どちらも指定した期間を超えたファイルです。したがって、削除対象を見分けるための期間を、書類を受け取ってからの経過だけで判断しないことが大切です。受け取った日が古いから消える、最近受け取ったから残る、と見た目だけで決めないようにします。

ファイルが今も残っていることだけをもって、削除しない設定になっているとは判断できません。書類の有無と、設定欄の選択値は別々に確認する必要があります。書類が残っていても、削除する期間が選ばれているなら、今の状態を記録したうえで保持する方針と照らし合わせます。

確認のために大切な書類を削除したり、削除条件を厳しくして動きを試したりする必要はありません。残すことが目的なら、削除を許可しない選択を確認し、残したい書類も開けるかを確かめる進め方にします。

3．共有端末は利用者の設定と管理側の設定を分けて確認する

選択した設定は自分にのみ適用され、同じ端末の別の利用者は自分の設定を管理できます。共有して使う端末では、確認した人の設定を、その端末を使う全員の設定として記録しないことが大切です。引き継ぎには、誰が使うときの状態を見たのかも残します。

Microsoft の管理者向けの案内では、管理担当者が組織の方針と利用者の要件に合わせて、動作を変更できます。

利用者側で選択を変えられない、または設定が元へ戻ったように見えるときは、その表示を控えて管理担当へ確認します。伝える内容は、残したい書類の保存先、現在の選択値、変更できたかどうかです。原因を先に決めず、画面で見えた事実と希望する扱いを分けて伝えるとよいです。

ストレージ センサーの対象は、Windows を含むシステム ドライブのみで、通常は C: です。保存先が別の場所にある書類を調べているときは、今見ている設定とその書類の場所が対応しているかを整理します。対象の範囲を広げて考えず、どの場所の何を残したいのかを具体的にしてから確認する流れです。

4．事務の記録は「残すもの」と「見た状態」を短くそろえる

ここからは当社の整理です。

受け取った書類を確認してから担当者へ渡す場面では、返答を待って残す書類と、処理を終えて整理する書類を分けます。確認待ちの見積書なら、次のように残す理由と設定の状態を記録します。

記録すること記入例
対象の書類確認待ちの見積書
残す理由担当者の返答を待っているため
対象の場所受け取った見積書を置いたフォルダー
設定で見た状態自動削除を許可しない選択になっている
書類の確認対象の書類が残り、開けることを確認
引き継ぐ内容返答後の保存先と整理の担当を決める

記録には、実際に確認したことだけを書きます。変更できなかった場合に、希望する状態をそのまま確認済みと書かないことが大切です。書類が残っているだけなら「残っていた」、選択値まで見たなら「選択値も確認した」と、記録の範囲をそろえます。

返答を待っている書類なら、返答後に誰が扱いを決めるかも残します。

5．設定を確認した後は、書類を置く流れを見直す

書類を残す設定を確認できた後は、受け取った書類をどこへ移し、誰が整理するかも見直すとよいです。一時的に置く場所と、担当者が確認を終えた書類の置き場を区別し、処理が済んだことを誰が判断するのかを決めます。

引き継ぎでは、未処理の書類を探す作業と、不要なものを処分する作業を分けておきます。

事務の手間を洗い出すなら、書類を受け取ってから保存先へ渡すまでの流れを整理し、AIで扱う事務作業を考える際の材料にできます。残すか処分するかの判断は担当者が担い、その前後で繰り返している確認や転記を分けておくとよいです。

6．確認表

公開・共有の前に、この表で確かめます。

確認確かめること
□残したい書類の保存場所を確認したか
□削除する対象の欄と現在の選択値を組にして確認したか
□実行する間隔と、削除対象の条件を別々に確認したか

□書類を残す理由と、次に扱いを決める担当者を記録したか
