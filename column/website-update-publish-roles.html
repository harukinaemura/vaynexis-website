サイトの更新担当と公開担当を分ける権限の選び方と承認の残し方

要点

WordPress の標準の役割を例に、更新担当には原稿を準備する範囲、公開担当には確認した内容を外へ出す範囲の権限を渡す、という順で整理します。担当名だけで選ばず、更新する対象と操作を先に決めることが出発点です。権限の設定に加え、誰がどの原稿を承認したかを記録する運用も用意します。使っているシステムが WordPress でない場合は、そのシステムの公式の説明で権限を確かめます。

公開：2026年11月3日／情報の確認日：2026年11月3日（出典はこの記事の最後）

この記事は、会社のサイトの更新を人に任せたい小さな会社の担当者が、更新と公開の権限、承認の記録を分けて決める流れをまとめたものです。

公式ページ・公式ヘルプなどの一次資料を2026年11月3日に確かめました。機能や制度は変わることがあるので、使う前に各ページで最新の状態を確認してください。法律・税務・労務の判断や、効果を約束するものではありません。

例は説明のための架空の例です。確認表や作例は、当社の考えをまとめたもので、公式の機関が示しているものではありません。

  1. 権限を選ぶ前に、更新する対象を決める
  2. 新しい投稿は、寄稿と公開の権限で分ける
  3. 画像・固定ページ・公開後の修正を切り分ける
  4. 公開待ちの状態と、社内の承認を分けて残す
  5. 担当者の権限を点検し、AIは原稿準備に使う
  6. 確認表
  7. 自社の事務の手順まで形にしたいとき

1．権限を選ぶ前に、更新する対象を決める

ここからは当社の整理です。

お知らせの文面を整えた人が、内容の確認を待ってから公開担当へ渡す場面を考えます。先に決めたいのは、「更新を任せる」という言葉の範囲です。文章を直すこと、画像を追加すること、公開済みの内容を差し替えることを、別の作業として書き出します。

依頼の内容は「お知らせの原稿を準備する」「掲載の可否を判断して公開する」のように、作業と責任が分かる表現にします。依頼の中に、会社紹介の書き換えやサイト全体の設定変更まで含めるかも明らかにするとよいです。

権限を選ぶ段階で困った操作を、そのまま担当者の権限拡大で解決しようとせず、公開担当や保守担当に渡す作業として残す方法もあります。引き継ぐ対象が明らかであれば、下書き担当の仕事の終点も決めやすくなります。

2．新しい投稿は、寄稿と公開の権限で分ける

新しい記事の原稿を準備する担当と、他の人の原稿を確認して公開する担当を分ける形から検討します。

WordPress の公式の説明では、標準の寄稿者は、自分の投稿を作成・管理できますが、公開はできません。編集者は、他のユーザーの投稿を含めて公開・管理できる役割です。一方、投稿者は自分の投稿を公開・管理できる役割です（確認日：2026-11-03）。

ここで検討する分担は、下書き担当と公開担当が別々のアカウントを使い、担当する操作だけを行う形です。これは当社の分担案です。公開の判断を別の人に残す目的に合わせ、役割を選びます。

公開担当に任せる対象も、担当する記事の範囲まで書き添えます。内容の公開を任せることと、利用者の追加やサイト全体の設定変更を任せることは、社内の依頼として分けておくとよいです。困った操作の連絡先は、権限を選ぶ担当とは別に決めておきます。

「原稿を書く人だから」という担当名だけで権限を決めると、任せたい操作と食い違うおそれがあります。選ぶ際には、文章を扱えるかに加えて、外へ出せるかも確かめることが大切です。

3．画像・固定ページ・公開後の修正を切り分ける

投稿の担当を決めた後は、原稿以外に必要な作業を分けて検討します。

同じく公式の学習ページでは、寄稿者は画像などのメディアファイルをアップロードできません。また、WordPress では、サイトに載せる内容に投稿と固定ページという区別があります（確認日：2026-11-03）。

画像の追加は公開担当へ渡し、原稿には使う画像と配置の希望を添える運用にすると、権限を広げる前に分担を整理できます。画像を受け取る担当と、文章を受け取る担当が異なる場合も、依頼先を原稿と一緒に残します。

会社紹介などの記事以外の更新や、すでに外へ出ている文章の差し替えは、新しい原稿を準備する作業とは別に扱います。投稿用に決めた分担をサイト全体へ広げず、対象の内容、変更する箇所、確認する人を先に決める形です。

当面の運用として、更新担当は変更案を別の文書で用意し、公開担当が承認された差分を反映する方法があります。画面上での編集まで任せたい場合は、必要な操作と公開を止めたい範囲を保守担当へ渡し、権限の設計を詰めるとよいです。

4．公開待ちの状態と、社内の承認を分けて残す

公開担当への引き継ぎには、原稿そのものと、掲載してよいという判断の記録をそろえます。

WordPress の公式の説明では、投稿の状態の一つ pending は、公開権限を持つユーザーによる公開を待つ状態とされています（確認日：2026-11-03）。

この状態を作業の目印にしつつ、社内で誰が内容を認めたかは、原稿と対応する記録として残す運用にします。「公開できる担当者」と「その文面を承認した人」は、分けて記入するとよいです。

残す項目記録する内容引き継ぐときの見方
更新の対象対象の記事や掲載場所別の内容を公開しようとしていないか
変更する範囲追加・修正する箇所と理由依頼されていない変更が混ざっていないか
確認対象の原稿保存場所と版を区別できる名前承認後に書き換わっていないか
内容の承認判断した人、判断した時点、承認・差し戻し誰の判断で進めるか分かるか
公開の担当操作する人と引き継ぎ先不在時にも連絡先が分かるか
公開後の照合承認した内容との一致、修正の要否掲載した内容を確認して区切れたか

表は当社の記録案です。承認の後に文面を直す場合は、直した範囲を示して再び確認へ戻す運用にします。公開担当が手元で修正した内容も、元の承認に含まれると扱わず、確認対象を明らかにします。

5．担当者の権限を点検し、AIは原稿準備に使う

分担を書面で決めた後は、担当者ごとの権限と依頼内容が合っているかを点検します。

公式の説明では、ユーザー一覧の Role 欄に、そのユーザーに割り当てられた役割が表示されるとされています（確認日：2026-11-03）。

確認用の環境を用意し、更新担当と公開担当それぞれの立場で、任せる操作と止める操作を確かめる手順を設けます。役割の名前を確認して終わりにせず、依頼した作業を進められるか、承認を待つ箇所で止められるかを見る考え方です。

AIを使う範囲は、文章の下書きや変更箇所の整理までとします。内容の承認と公開の判断は人が行う分担案です。AIへ渡す材料も、原稿準備に必要なものに絞り、実際の公開操作とは切り離して扱います。

担当が交代したときには、原稿の受け渡し先と公開を判断する人を更新します。操作できる人の一覧と、社内の承認の連絡先を一緒に見直すことで、引き継ぎを区切りやすくなります。

6．確認表

公開・共有の前に、この表で確かめます。

確認確かめること
□更新担当が準備する範囲と、公開担当が反映する範囲を分けたか
□下書き担当が公開できない分担になっているかを確認したか
□画像追加と記事以外の更新を誰に渡すか決めたか

□公開する担当と不在時の引き継ぎ先を決めたか
□担当者ごとの操作範囲と、掲載後の内容を確かめたか
