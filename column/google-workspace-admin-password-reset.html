社員がパスワードを忘れたときの管理者による再設定と復旧確認（Google Workspace）

要点

Google Workspace を使う会社で社員がパスワードを忘れたときは、本人と対象を照合したうえで、権限のある担当者が再設定し、本人への引き渡しと復旧確認までをつなぐ運用にします。画面での処理と、本人による変更・入り直しを別々に確かめ、受付記録には秘密の値を残さないようにします。

公開：2026年11月4日／情報の確認日：2026年11月4日（出典はこの記事の最後）

この記事は、Google Workspace を使う小さな会社の事務担当者が、社員がパスワードを忘れたときの本人確認・再設定・復旧確認と記録の残し方を確かめる流れをまとめたものです。

公式ページ・公式ヘルプなどの一次資料を2026年11月4日に確かめました。機能や制度は変わることがあるので、使う前に各ページで最新の状態を確認してください。法律・税務・労務の判断や、効果を約束するものではありません。

例は説明のための架空の例です。確認表や作例は、当社の考えをまとめたもので、公式の機関が示しているものではありません。

  2. 管理画面で対象を選び、本人の変更を求める
  3. 本人への通知とログイン状態のリセットを進める

1．受付では依頼者と対象を照合する

確認日：2026-11-04

ここからは当社の整理です。

受付では、依頼を受けた経路、本人を確かめた方法、操作対象を整理します。本人確認の方法は社内で定め、対面や社内に登録された連絡先への折り返しなどで照合する運用にします。依頼文に書かれた新しい連絡先だけを頼りに処理を進めず、社内で把握している連絡先との照合を挟む形です。

操作対象は、表示名だけでなく所属と会社で使うメールアドレスを突き合わせます。受付担当者から管理者への引き渡しでは、本人確認を済ませたことと、対象の照合結果を伝えます。急いでいることと確認が済んでいることは、記録を分けて扱うとよいです。

また、本人が今利用できる連絡経路も先に相談します。受付のメモには、新しく渡すパスワードを書き込む欄を設けません。対応の進み具合を共有する記録と、本人だけに渡す秘密の値を分けるためです。

2．管理画面で対象を選び、本人の変更を求める

Google Workspace の公式ヘルプによると、ユーザーのパスワードを再設定するには、パスワード再設定権限を持つ管理者アカウントでログインする必要があります。

対象を照合して再設定を開く

ヘルプの手順では、Google 管理コンソールの［ユーザー］一覧で対象にカーソルを合わせ、右側の［パスワードを再設定］を選択します。

ここでは、受付時に確認した対象と、画面で選んだ対象を照合します。依頼を読んだ担当者と操作する担当者の間で、名前の取り違えがないかを確かめる場面です。

新しいパスワードと変更要求を設定する

ヘルプによると、管理者が新しいパスワードを入力する方法では、再設定画面の［パスワードを作成する］を選びます。作成時には、［ユーザーにパスワードを変更してもらう］をオンにして、本人が次回ログイン時に変更する設定にします。設定を確かめた後、［リセット］を選択します。

入力した値を共有用の受付記録へ貼り付けず、本人への引き渡しに進みます。管理者が設定した値をそのまま使い続ける前提で案内せず、本人が変更するところまでを復旧確認に含める運用です。

3．本人への通知とログイン状態のリセットを進める

ヘルプでは、本人への通知に、再設定後の画面の［パスワードをコピー］で値をコピーして渡す方法があります。メールで通知する際は、本人が受信できるメールアドレスに送信します。

送付前には、受付時に照合した本人への連絡経路と宛先を見比べます。送信した事実と、本人が受け取れたことは分けて確認する運用にするとよいです。

公式ヘルプでは、パスワードの再設定後に、対象ユーザーのログイン Cookie もリセットする必要があるとしています。パスワードとログイン Cookie の再設定後は、すべてのアクティブなセッションからログアウトされます。

本人には、作業を再開する前に入り直すところまで付き合う流れを伝えます。管理画面の処理が終わった時点で受付を閉じず、本人からの復旧連絡を待つ形です。

4．復旧記録には秘密の値を残さない

引き継ぎ用の記録には、何を確かめ、どこまで対応したかを残します。受付から復旧確認までを同じ担当者が続けられない場面でも、後任が本人への連絡を引き継げる形にします。

記録する項目架空の記入例
本人確認社内に登録済みの連絡先へ折り返し、依頼を照合済み
対象の照合所属と会社で使うメールアドレスを照合済み
対応状況管理者の処理を終え、本人へ引き渡し済み
本人による確認本人の変更と入り直しを確認済み
未解決事項と引き継ぎ先業務で使う画面の利用確認を担当者が継続

受付記録には対応した担当者も添えます。新旧のパスワードや、本人に代わってログインするための情報は記入せず、完了した操作と連絡結果を文章で残す形です。

復旧の連絡を受けた後は、本人が必要な仕事に戻れたかを尋ねます。入り直せたことと、業務で使う画面を開けたことを分けて聞くと、確認が途中の項目を引き継ぎやすくなります。

5．操作できない場面は権限と認証経路を確かめる

ヘルプによると、適切な権限がない場合、必要な設定が一部表示されないことがあります。管理者が扱える範囲や実行できる作業は、割り当てられたロールの権限で決まります。表示されない操作については、権限を管理する担当者に確認する流れにします。

外部の認証サービスからログインする構成にも注意が必要です。ヘルプによると、Google Workspace は、外部の ID プロバイダを使うシングル サインオン（SSO）に対応しています。自社の認証経路を管理する担当者と、どのパスワードを忘れたのかを照合する運用にします。

また、ヘルプでは、別の管理者のパスワードを再設定するには、特権管理者の権限が必要とされています。一般社員からの依頼と管理者自身の復旧依頼を分け、対応できる担当者へ引き継ぎます。
