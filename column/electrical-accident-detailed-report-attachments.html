電気事故報告書（詳報）は何をそろえる？添付資料と提出前の整理

要点

電気事故報告書（詳報）の準備では、定期点検の書類、単線結線図、死傷事故では診断書の写しを可能な範囲でそろえます。事故の説明と元資料を対応させ、技術的な内容の確認を経て、提出する一式をまとめる進め方です。

公開：2026年11月16日／情報の確認日：2026年11月16日（出典はこの記事の最後）

この記事は、電気事故の詳報に添える資料をそろえたい小さな会社の担当者が、点検記録・図面・診断書と提出用データを確かめる流れをまとめたものです。

公式ページ・公式ヘルプなどの一次資料を2026年11月16日に確かめました。機能や制度は変わることがあるので、使う前に各ページで最新の状態を確認してください。法律・税務・労務の判断や、効果を約束するものではありません。

確認表や記録項目は当社の整理です。公式機関が示す様式ではありません。

  1. 報告する相手と、資料の対象を分けて確認する
  2. 入力前に、点検記録と図面の所在を押さえる
  3. 感電死傷事故と波及事故で、説明資料を組み替える
  4. 提出するデータと、修正を続けるデータを残す
  5. 元の記録から提出用の一式までをつなぐ
  6. 引き継ぎには、確認者と提出後の対応まで含める
  7. 確認表
  8. 自社の事務の手順まで形にしたいとき

1．報告する相手と、資料の対象を分けて確認する

確認日：2026年11月16日

NITE の案内では、電気関係報告規則に該当する事故について、事業者が詳報を作成し、経済産業省の本省又は設置場所を所轄する産業保安監督部へ提出する必要があります。 事故を起こした電気工作物や事故の種類によって、詳報に記載を求められる内容は異なります。

NITE の「詳報作成支援システム」の案内ページでは、使い方マニュアルの更新日は2026年7月3日と表示されています。 一方、その PDF 本体は、2024年4月1日時点のシステム利用方法をまとめた資料と明記しています。 以下の事故別の準備項目とメール報告の流れは、このマニュアルの記載範囲です。

報告書に記載する内容の相談先は管轄の保安監督部又は経済産業省、システムの使い方の相談先は NITE と案内されています。 適用の可否は、公式資料を示して専門家に確認します。

2．入力前に、点検記録と図面の所在を押さえる

NITE の事業用詳報の入力前案内は、年次・月次等の定期点検の書類、死傷事故については診断書の写し、単線結線図の準備を挙げています。 これらは「可能な範囲で」とされており、この案内だけから、すべての事故で同じ添付書類が一律に必要とは読み取れません。

書類を集める際は、資料の有無だけでなく、どの設備のどの状態を示すかを照合するとよいです。事故に関係する機器と、図面や点検記録に書かれた名称が結び付かない場合は、現場の担当者に対応関係の確認を依頼します。事務担当者が似た名称から設備を推定して、別の記録を付ける扱いは避けます。

点検記録は、必要な頁を抜き出す前に原本の所在を控え、記録の対象設備と実施時点が分かる状態で受け取ります。図面についても、現場の状態と合うかを技術担当者に確かめてもらう流れです。資料が届いていない箇所には確認する相手を付け、報告書の文章だけを先に完成扱いにしない整理が役立ちます。

3．感電死傷事故と波及事故で、説明資料を組み替える

マニュアルの感電死傷事故の例では、主な準備項目として、感電経路、事故時の安全装備状況、経験年数、安全教育、充電部の状態が挙げられています。 同じ例の添付書類には、使用区域平面図、単線結線図、作業状況図、感電負傷箇所、診断書、保守点検記録等が列挙されています。

波及事故の例では、地絡・短絡事故の発生原因である１次要因と、波及事故に至った原因である２次要因を分けて示しています。 その例の添付書類は、使用区域平面図、単線結線図、保守点検記録等です。

原因に関する調査結果を受け取る際は、どの説明がどの設備についてのものかを技術担当者に確認してもらいます。損傷した設備の記録と、周囲への影響を説明する記録を、同じ理由の資料としてまとめてしまうと、報告書の説明との対応が曖昧になります。原因の選択や対策の妥当性を事務担当者が判断する扱いにはしません。

4．提出するデータと、修正を続けるデータを残す

NITE は、詳報作成支援システムに入力データをサーバー上に残さないため、作業終了時に XML ファイルを保存するよう求めています。 PDF ファイルだけでは、作業途中からの再開はできません。

マニュアルのメール報告方法では、詳報の PDF・XML の保存、任意の写真 PDF の作成、書類の添付、監督部へのメール提出という流れが示されています。 写真 PDF の作成は任意です。 写真をまとめる場合は、どの箇所を写したものかを文章や図面と対応させ、画面上で読める大きさと向きを確かめておくとよいです。

NITE の XML テンプレートは、架空の事故の概要・原因・再発防止対策の具体例を記載したものです。 利用時は、あらかじめ記載されたテキストを実際の事故報告内容に修正するよう案内されています。 下書きの表現が整っていても、元の記録と一致するかの確認は別に行います。

5．元の記録から提出用の一式までをつなぐ

ここからは当社の整理です。

社内で集める資料を、そのまま全部提出する一式と考えないことが大切です。本文に書く内容の裏付け、説明を補う添付候補、社内で確認に使う資料を分け、最終的に提出する範囲は報告の責任者が確認します。資料を受け取った時点で、対応する説明と確認者を付けておくと、修正時にも元の記録へ戻れます。

元の記録下書きとのつなぎ方提出・保管へ引き継ぐもの
発見・連絡・応急対応のメモ発生経過の各記述に情報源を付ける確認済みの経過と元メモの所在
機器の表示、図面、点検記録記述した設備と資料の対象を照合する技術担当者の確認済み資料と原本の所在
現場や損傷部の写真文章と図面のどの箇所に対応するかを付ける提出候補の写真と説明
調査結果と対策の記録確認した内容、実施済み、予定を区別する責任者が確認した説明と確認待ちの問い
提出用にまとめた書類とデータ下書きからの変更点を照合する送った一式、送付の記録、再編集用データ

写真や図面を差し替えた際は、対応する説明も読み直します。本文には古い機器名が残り、添付だけが新しくなるような食い違いを防ぐためです。調査で説明が変わった場合も、直前の下書きを消してしまわず、変更した箇所と確認した相手が追えるように残すとよいです。

6．引き継ぎには、確認者と提出後の対応まで含める

引き継ぎでは、収集を終えた資料と、確認を待つ資料を分けます。提出期限、使用する書式、送付方法について窓口へ確認した内容は、誰がいつ確認したかとともに控えます。窓口ごとの書式や送付方法の扱いは、提出先への確認事項として残す進め方です。

現場の担当者には設備と事実関係、技術担当者には調査内容、報告の責任者には提出する説明と添付の範囲を確認してもらう分担が考えられます。事務担当者は、説明の食い違いを勝手に統一せず、どちらを確認すべきかが分かる問いとして渡します。確認待ちの項目には、次に動く担当者と返答を受ける予定を添えるとよいです。

送付後は、送った書類とデータ、送付の記録、その後の照会内容を同じ案件からたどれる状態で保管します。追加資料の依頼を受けた場合も、どの記述についての依頼かを元の一式と対応させ、差し替えか追加かを区別して引き継ぎます。

事務の手間を洗い出すなら、資料の受け渡しと内容確認が滞る箇所を分けて、業務の流れを見直す観点から整理するとよいです。

7．確認表

公開・共有の前に、この表で確かめます。

確認確かめること
□事故の説明と、必要な資料の範囲を確認する相手を明らかにしたか
□点検記録・図面が対象とする設備と、報告する設備を照合したか
□写真の箇所と説明、図面との対応を確認したか
□調査結果と対策の説明について、技術担当者と責任者が確認したか
□提出期限・書式・送付方法を、提出先に確認した内容と照合したか
□提出用の一式、再編集用のデータ、送付の記録を保管する担当を明らかにしたか

8．自社の事務の手順まで形にしたいとき

ここまでの確認を、自社の事務の手順書や、AIの結果を確かめる検査まで形にしたい場合は、当社のように、手順と検査の設計まで行う相談先が選択肢になります。オンラインは全国から対応しています。

自社の事務のどこから確認を入れるかを相談したい場合は、初回無料相談をご利用ください。法律・税務・労務の判断や、効果の約束は行いません。
