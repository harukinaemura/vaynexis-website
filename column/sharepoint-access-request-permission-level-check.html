SharePointのアクセス要求で、承認前にどの権限を確認する？

要点

SharePointサイトのアクセス要求は、要求したアカウント、必要な資料や作業、承認できる範囲を照合します。保留中の要求を開き、必要な作業に合うアクセス許可レベルを確認してから承認・拒否を選びます。判断した日と確認した内容も残します。

公開：2026年11月10日／情報の確認日：2026年11月9日（出典はこの記事の最後）

この記事は、SharePointサイトに届いたアクセス要求を処理したい小さな会社のサイト担当者が、要求の相手と対象、付けるアクセス許可レベル、処理の記録を確かめる流れをまとめたものです。

公式ページ・公式ヘルプなどの一次資料を2026年11月9日に確かめました。機能や制度は変わることがあるので、使う前に各ページで最新の状態を確認してください。法律・税務・労務の判断や、効果を約束するものではありません。

確認表や記録項目は当社の整理です。公式機関が示す様式ではありません。

  1. 保留中のアクセス要求を開く
  2. 要求した相手と対象を照合する
  3. 許可する範囲に合う権限を選ぶ
  4. 承認・拒否と確認した内容を残す
  5. 確認表
  6. 自社の事務の手順まで形にしたいとき

1．保留中のアクセス要求を開く

確認日：2026年11月9日。

Microsoftの日本語ヘルプでは、SharePointサイトで［設定］から［サイトのコンテンツ］を開き、［アクセス権の要求］で保留中の要求を確認します。保留中の要求がある場合にボタンが表示されると案内されています。

ここからは当社の整理です。

通知を受け取ったら、まず管理するサイトを特定します。複数のサイトに似た名前の資料がある場合は、サイトと対象の場所を確かめてから要求を開きます。

Microsoftの案内では、既定でアクセス要求のメールを受け取る人はサイトの種類で異なります。グループに接続されたサイト（Microsoft Teams を含む）はグループ管理者、コミュニケーション サイト、グループのないモダン サイトとクラシックのサイトは所有者グループのユーザー、OneDrive とプロジェクト サイトはプライマリ サイト管理者です。また、サイトでメールが有効なセキュリティ グループを使っている場合は、サイト所有者がアクセス要求のメールを受け取らない可能性があるとされています。

同じページの［SharePoint］の欄では、サイト所有者が［設定］、［サイトのアクセス許可］の順に進み、［サイト共有］の［メンバーの共有方法を変更］で［アクセス要求の許可］をオンにし、要求を受け取る人としてサイトの所有者か特定のメール（特定のユーザーまたは配布リスト）を選びます。アクセス要求のページで相手に表示するメッセージも追加できます。［SharePoint Server］の欄では、［サイトのアクセス許可］から［詳細アクセス許可の設定］を開く手順になっています。

通知が自分に届かない設定のサイトもあるため、通知の有無だけで要求が無いと判断せず、［サイトのコンテンツ］に［アクセス権の要求］が出ていないかも見ます。使っている製品がどちらの欄に当たるかは、サイトの管理担当に確かめます。

2．要求した相手と対象を照合する

要求したアカウント、対象の場所、必要な作業を照合します。閲覧するだけか、資料を編集する必要があるかを分けて確認します。相手や要求内容が特定できない場合は、担当に照会して回答が得られるまで判断を保留します。

Microsoftの案内では、サイトの所有者ではないユーザー（サイトのフル コントロール アクセス許可を持たないユーザー）が［共有］コマンドで他の人を招待すると、サイトの所有者へのアクセス要求が作られます。サイトにだれがアクセスでき、どの権限レベルを割り当てるかの最終的な決定権は、サイト所有者にあるとされています。要求の中には、本人からの要求のほかに、メンバーが同僚や社外の人を招待したことで作られたものもあります。招待した人と、アクセスを得る人の両方を確かめます。

社外の利用者が含まれる場合は、共有できる対象と範囲をサイトの管理担当に確かめます。承認の記録には、誰からどの情報を確認したかを残します。

3．許可する範囲に合う権限を選ぶ

公式ヘルプは、［保留中の要求］で対象の要求の省略記号を開き、承認する場合は［アクセス権］でユーザーに割り当てるアクセス許可レベルを選択する手順を示しています。

Microsoft Learn の権限レベルの説明（SharePoint in Microsoft 365）では、既定のアクセス許可レベルのうち、［フル コントロール］は使用可能なすべての SharePoint の権限を含み、既定では所有者グループに付きます。［編集］はリストの追加・編集・削除と、リスト アイテムとドキュメントの表示・追加・更新・削除ができ、既定ではメンバー グループに付きます。［投稿］はリスト アイテムとドキュメントの表示・追加・更新・削除ができます。［読み取り］はページとアイテムの表示とドキュメントのダウンロードができます。［表示のみ］は表示ができますが、サーバー側のファイル ハンドラーを備えたドキュメントは、ブラウザーで表示できてもダウンロードはできません。

同じ説明では、チーム サイトには所有者グループ、メンバー グループ、閲覧者グループが自動的に含まれ、閲覧者グループのレベルは［読み取り］です。サイトに既定で含まれるグループとレベルはサイトのテンプレートなどで異なる場合があり、SharePoint 管理者が独自のグループと権限レベルを作ることもできるとされています。

要求の理由に照らし、閲覧や編集など必要な操作と選択肢の範囲を見比べます。表示される権限が目的より広い、または必要なものが見つからない場合は、対象を絞って付与できるかをサイトの管理担当へ確認します。資料を読むだけなら［読み取り］か［表示のみ］、資料を直す必要があるなら［投稿］か［編集］のように、まず必要な操作から候補を絞ります。［表示のみ］ではダウンロードできない資料があること、［編集］ではリストの追加や削除もできることを、選ぶ前に確かめます。［フル コントロール］は既定で所有者グループに付くレベルのため、要求の承認で付ける前に管理担当へ相談します。

4．承認・拒否と確認した内容を残す

Microsoftは、要求画面で承認または拒否を選べることと、過去の要求は［履歴の表示］で見られることを案内しています。同じ手順では、アクセスを要求しているユーザーにメッセージを入力することもでき、決定を記録するのに便利なことがあるとされています。

処理した日、対象の要求、承認または拒否、承認時に付けた権限と理由を控えます。メッセージの欄に、承認した範囲や拒否の理由を短く書いておくと、相手にも判断の内容を示せます。

Microsoftの案内では、［アクセス要求］のページを使う権限があるのは、サイト コレクション管理者、Microsoft 365 の SharePoint 管理者、サイトの既定の所有者グループのメンバーだけです。所有者グループから外された後にサイトのフル コントロールを付与されたユーザーは、このページへのアクセスを拒否されるとされています。

必要な画面を開けない場合は、サイト名と保留中の要求を確認できない状況を管理担当に伝え、権限がある担当へ引き継ぎます。フル コントロールを持っていても開けない場合があるため、所有者グループに入っているかも合わせて伝えます。

□処理結果と判断の根拠を控えたか
