スキルマトリックスの記入項目｜習熟段階・確認根拠・更新日の書き方

要点

スキルマトリックスには、担当者と作業の対応に加え、どこまでできるかを表す習熟段階、その判断を支える確認根拠、確認者、確認日、更新日を設けます。段階の意味は作業の範囲と結び付けて言葉で定義し、まだ確かめていない状態も区別します。記号だけで判断せず、何を見て、いつ確かめたかをたどれる表にする整理です。

公開：2026年11月3日／情報の確認日：2026年11月3日（出典はこの記事の最後）

この記事は、スキルマトリックスを作る小さな会社の管理者・事務担当者が、習熟段階・確認根拠・確認日・更新日の欄をどう書き分けるかを整理するためのものです。

公式ページ・公式ヘルプなどの一次資料を2026年11月3日に確かめました。機能や制度は変わることがあるので、使う前に各ページで最新の状態を確認してください。法律・税務・労務の判断や、効果を約束するものではありません。

例は説明のための架空の例です。確認表や作例は、当社の考えをまとめたもので、公式の機関が示しているものではありません。

  1. 担当者と作業を結び付け、判断の根拠まで欄にする
  2. 習熟段階は、作業範囲と支援の要否で定義する
  3. 確認根拠には、観察した内容と記録の所在を残す
  4. 本人と確認者は、段階より先に対象範囲を照らす
  5. 確認日と更新日を分け、変更の理由を残す
  6. 確認表
  7. 自社の事務の手順まで形にしたいとき

1．担当者と作業を結び付け、判断の根拠まで欄にする

マネーフォワードの公式ページには、スキルマトリックスのひな形が掲載されています（確認日：2026-11-03）。厚生労働省の「職業能力評価シート」は、習熟度をチェックする本体と、具体的な知識や能力を記した補助資料で構成されています（確認日：2026-11-03）。

ここからの項目と記入例は当社の整理です。担当者を縦、作業を横に並べる対応表に、段階の定義と確認記録を添える形を考えます。対応表を見てから、その判断に使った記録へたどれる構成です。

項目何を書くか記入例書き間違えやすい点
担当者対応する人を識別できる呼び名担当甲同じ呼び名の人を区別しない
作業名確かめる作業の名称備品申請の受付部署全体の仕事を広くまとめる
作業範囲開始から完了までの対象範囲申請内容の照合から受付簿への記入まで作業名だけで対象を決める
到達状態完了時に確認する状態必要な欄を照合し、受付内容を記録できる「理解している」だけで終える
習熟段階定義に照らして確認した現在の状態支援あり段階の意味を人によって変える
段階の定義支援の要否と、確認する行動確認者の助言を受けながら対象範囲を終えられる色や記号だけを決める
確認根拠見た作業や記録、その所在受付の練習記録。申請内容の照合に助言あり感想だけを書く
確認者作業や記録を確かめた人確認担当入力した人と混同する
確認日対象の作業を確かめた日練習を確認した当日表を編集した日に置き換える
更新日表の記載を変更した日確認結果を反映した当日再確認せず段階まで新しく扱う

例のように確認記録の内容を短く添え、詳しい記録の所在を残します。対応表の各マスには習熟段階を置き、担当者と作業の組み合わせを使って確認記録を探せるようにするとよいです。長い説明を各マスへ詰め込まず、見渡す部分と読み込む部分を分けます。

2．習熟段階は、作業範囲と支援の要否で定義する

段階名には、「未確認」「支援あり」「自立」「説明可能」などの言葉を使う整理が考えられます。それぞれに、どの範囲を、どのような支援を受けて進められる状態なのかを書き添えます。段階名と定義を近くに置き、記入者が同じ意味で選べる形にします。

「支援あり」は助言や途中確認を受けて対象範囲を終えられる状態、「自立」は定めた手順と確認項目に沿って対象範囲を進められる状態、といった定義です。「説明可能」は手順と確認する理由を他の担当者へ説明できる状態として分けます。作業を行えることと、人へ説明できることは、それぞれ確かめて記載します。

また、通常の処理と例外への対応は区別して残します。通常の処理を進められるという記載から、例外の判断までできると読み広げないためです。判断を相談する相手や、本人に任せる範囲は、作業範囲の欄で明らかにするとよいです。

「未確認」は、まだ判断に使う確認を行っていない状態です。未経験、確認待ち、対象外も言葉を分け、記入していないマスの意味を読み手の推測に任せません。段階を上げ下げする前に、対象範囲と確認状況を照らす進め方にします。

3．確認根拠には、観察した内容と記録の所在を残す

根拠の欄には、対象とした作業、見た記録、助言を要した箇所、完了時に確かめた内容を短く残します。「慣れている」「問題なし」という感想だけでは、後から判断を読み直しにくいためです。担当した経験の記録と、対象範囲を進められることの確認は、分けて記載します。

研修を受けた記録は、受講を確かめる材料として扱います。実際の作業を確認する欄とは区別し、何を確かめた根拠なのかを明記するとよいです。知識について聞き取った内容も、作業を観察した内容に置き換えず、そのまま残します。

記録の所在は、表を使う担当者が探せる書き方にそろえます。資料名だけで区別しにくい記録には、対象の作業や記録を識別する情報を添えます。表から元の記録へたどり、根拠に書いた内容と照らせる状態が目安です。

確認に使った記録の全内容を、対応表へ写す必要はありません。表には判断に関係する内容を絞って記し、詳細は管理先に残します。確認者の交代に備え、本人の記憶だけに頼らず説明できる記録を整えます。

4．本人と確認者は、段階より先に対象範囲を照らす

記入時は、本人と確認者が同じ作業範囲を見ているかを照らします。作業名が同じでも、準備から完了後の確認までを含むのか、途中の処理だけなのかで、判断の対象が変わります。段階の選び方を話し合う前に、作業範囲と到達状態を読み合わせる進め方です。

続いて、確認根拠に書いた内容と、助言を受けた箇所を確かめます。認識の違いは、対象の範囲、見た場面、支援の内容に分けて記録するとよいです。相手の説明を短い段階名だけにまとめず、違いが残っている箇所を具体的に書きます。

判断がまとまらない欄は、確認待ちとして残し、次に確かめる作業と確認する相手を添えます。根拠がそろっていない段階で、自立などの記載へ置き換えません。確認後に、根拠と段階を合わせて更新する流れにします。

5．確認日と更新日を分け、変更の理由を残す

確認日は、作業や記録を確かめた日です。更新日は、その内容を表へ反映した日として分けます。転記や表記の修正だけを行った更新と、作業を改めて確かめた更新を区別できるよう、変更の理由も短く添えます。

手順の変更や担当範囲の変更を、表を見直すきっかけにします。以前の確認がどの手順に基づいていたかを残し、新しい手順で確認する内容を整理するとよいです。担当者名の変更など、作業の習熟とは関係のない修正も区別します。

閲覧する人、編集する人、確認結果を承認する人を社内で決め、最新版の保管先をそろえます。過去の段階と根拠は、変更の経緯をたどれる形で残します。表そのものの更新担当と、各作業を確かめる担当も明らかにしておくと、確認待ちの欄を引き継げます。

6．確認表

公開・共有の前に、この表で確かめます。

確認確かめること
□担当者と作業の組み合わせを識別できる欄を用意したか
□作業名に加え、対象範囲と到達状態を言葉で定義したか
□習熟段階ごとの支援の要否と、確認する行動を明確にしたか
□未確認、確認待ち、対象外を区別する記入方法を決めたか
□判断に使った作業や記録の所在、確認者を記載したか
□確認日と更新日を分け、変更の理由を残す欄を用意したか
□閲覧・編集する担当者と、最新版の保管先を決めたか

7．自社の事務の手順まで形にしたいとき

ここまでの確認を、自社の事務の手順書や、AIの結果を確かめる検査まで形にしたい場合は、当社のように、手順と検査の設計まで行う相談先が選択肢になります。オンラインは全国から対応しています。

自社の事務のどこから確認を入れるかを相談したい場合は、初回無料相談をご利用ください。法律・税務・労務の判断や、効果の約束は行いません。
